## Included

- Standardized shared responsive storefront UX across breakpoints. (#1652)
- POS Items workspace loads again — repairs `fetchPosCatalogPage`'s three undefined identifiers.
  Already shipped to production as a direct `main` hotfix (candidate 2026-09-07-02); this candidate
  brings `staging`/`develop` back to parity with it. (#1698, PR #1702)
- New local synchronous compliance-declaration reconcile tool, avoiding a CI round trip for a
  Worker actively authoring a declaration. (#1694, PR #1703)
- `promotion-quality-gate.yml`'s `repository-quality` job split into 3 concern-based jobs. (#1690,
  PR #1705)
- `fix/*` hotfix-to-`main` PRs now route to GitHub-hosted build-check runners instead of the
  self-hosted pool. (#1701, PR #1711)
- Import-graph-aware fan-out reachability audit for `packages/web-core`, shipped in shadow mode
  (no enforcement yet). (#1695, PR #1708)
- New promotion-time divergence check between `develop` and `staging`, run by the Promoter role
  ahead of every `to-staging/<candidate_id>` cut. (#1696, PR #1704)
- Per-app version floor bump (`dgfy-api`, `dgfy-migration-runner`, `dgfy-ims`, `dgfy-pos`) ahead of
  this candidate, per ADR 0081 Decision 6.
- **Repair (r1):** fixed `resolve-build-plan`'s `Cannot find module 'madge'` crash blocking every
  STAGING/PROD deploy — `deployment-orchestrator.yml` and `deploy-main.yml` both ran
  `resolve-build-skip-plan.js` (which needs `madge`, a devDependency, via
  `check-app-version-bump.js`/`resolve-web-core-reachability.js`) with no `npm install` step at
  all. Added a `Setup Node.js` + `npm ci` step to both jobs, mirroring
  `promotion-quality-gate.yml`'s own root-level install pattern. (#1716)
