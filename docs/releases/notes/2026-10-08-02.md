## Included

- Fixes the recurrence of "Data truncated for column 'reference_type'" on POS parked-sale
  park/resume/re-park for every tenant provisioned before 2026-10-07. The prior hotfix (PR #2322)
  widened `stock_movements.reference_type`'s ENUM on the landlord database and the Sequelize
  model only; it never registered the change in the tenant-schema drift-repair registry
  (`apps/dgfy-api/scripts/sync-tenant-schemas.js`), so no existing tenant's physical table was
  ever repaired. Confirmed empirically against all 52 production tenants before this fix: every
  one was still missing `'POS_PARKED_SALE'`. Also closes the gap in
  `check-tenant-schema-registry-coverage.js` that let this ship unnoticed — it had no detection
  for `queryInterface.changeColumn(...)`, the exact call PR #2322's migration used. (#2335)

## Operational notes

This candidate has no staging soak — released as a main hotfix outside the normal promotion flow.
See docs/ops/RELEASE_CANDIDATE_POLICY.md's "Hotfix and back-port" section for the authorization
record.

The actual tenant-schema repair is automatic: `infrastructure/docker/dgfy-api/entrypoint.sh`'s
existing non-blocking `repair-apply` step runs on every API container start/restart and will
widen every active tenant's `stock_movements.reference_type` column as soon as this deploy
restarts the container — no separate manual production DB command is required. Verify post-deploy
by dispatching `tenant-schema-report.yml` (read-only) and confirming `failed_tenant_count: 0`.
