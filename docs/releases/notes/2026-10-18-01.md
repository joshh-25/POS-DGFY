## Included

- Storefront serves Android and iOS app-link association files from the production apex domain. Android verification remains pending signing fingerprints. (#2555, #2552)
- Storefront order-status changes can send deduplicated push notifications when Expo delivery is configured; delivery remains disabled by default. (#2557, #2554)
- PayMongo commerce refunds have scheduled recovery, operator alerts and retry controls, with refund status visible in order tracking. (#2556, #2549)
- POS uses shared backend-reachability handling to keep checkout and terminal recovery behavior consistent during network outages. (#2564, #1476)
- POS staff devices can register Expo push tokens and receive a generic new-online-order wake-up after a fresh online checkout, with server-side authorization and location checks; the incoming-orders polling route remains authoritative and provider enablement is environment-configured. (#2569, #2571)
- Tenant database acquire-timeout diagnostics include request and pool context; tenant capability reads use a short in-process cache. (#2565, #2560)
- DGLaundry runtime origins now come from deployment configuration, and reviewed connection setup materials and environment pins are included. Applying the production host patch remains a separate operator action after this code reaches production. (#2551, #2553, #2547, #2548, #2304)

## Operational notes

DGLaundry production setup is not performed by this promotion. Apply the reviewed production host patch only after the DGLaundry origin configuration change reaches production, following `infrastructure/dglaundry/README.md`.

Expo push delivery remains disabled in PROD. Enable it after `PUSH_PROVIDER=expo` and a dedicated `PUSH_TOKEN_HASH_SECRET` are provisioned in SOPS; `EXPO_ACCESS_TOKEN` is optional for enhanced push security.
