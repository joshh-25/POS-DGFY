## Included

- Retail orders now preserve scheduled fulfillment selection, issue inventory at acceptance, and reverse that issue exactly once on post-acceptance cancellation or rejection. (#1931, PR #1936)
- POS owners can assign eligible cashier accounts to registered terminals while preserving legacy location-based access when no explicit assignment exists. (#1932, PR #1935)
- DGLaundry partner requests now use RFC 9421 P-256 signatures with shared Redis replay protection and fail-closed production behavior when Redis is unavailable; provider admission remains disabled pending hosted qualification. (#519, PR #1920)

## Operational notes

- Development and staging API vhosts now proxy to the active backend ports instead of retired mobile-auth ports. (#1928, #1929, PR #1930)
- The DGLaundry integration still requires provider key/client configuration and hosted qualification before enablement.
