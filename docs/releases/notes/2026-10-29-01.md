## Included

- POS now waits for tenant-session activation before protected store-settings, receipt-settings, catalog, and catalog-event requests. This prevents production checkout from requiring a manual browser refresh when the session is still being established. (#2918)
- POS no longer mounts protected settings while the account is anonymous; it shows the sign-in state instead of exposing a raw 401 authentication error, then mounts settings automatically after login. (#2918)

## Operational notes

This candidate has no staging soak — released as a main hotfix outside the normal promotion flow.
See docs/ops/RELEASE_CANDIDATE_POLICY.md's "Hotfix and back-port" section for the authorization
record.

No database migration is included. The IMS, POS, Storefront, OPIS, and Admin patch bumps are
the shared `packages/web-core` fan-out required for the protected-session ordering fix.
