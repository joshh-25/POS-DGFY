## Finding Description
The landlord `tenants` table and `Tenant` model exposed `db_username` and `db_password` as plaintext columns.  
Even when empty, this left a latent path for future plaintext credential storage.

## Root Cause
- Early multi-tenant schema design included per-tenant DB credential fields.
- Runtime implementation later standardized on environment credentials (`DB_USER` / `DB_PASSWORD`) and stopped using tenant-level credential fields.
- Schema/model cleanup was never completed, leaving sensitive columns in place.

## Evidence Collected
1. Column definitions existed before this fix:
   - `backend/migrations/20260131000002-create-tenants-table.cjs` (`db_username`, `db_password`)
   - `backend/src/models/Landlord/Tenant.js` (`db_username`, `db_password`)
   - `docs/database/schema.md` included both columns in landlord schema docs.
2. Runtime did not use tenant-stored credentials:
   - `backend/src/utils/TenantConnector.js` uses `process.env.DB_USER` / `process.env.DB_PASSWORD`.
   - `backend/src/services/tenantProvisioningService.js` uses `process.env.DB_USER` / `process.env.DB_PASSWORD`.
3. Live data check (before migration apply) showed no populated tenant credential rows:
   - `total = 2`, `with_db_username = 0`, `with_db_password = 0`.

## Final Implementation
1. Removed tenant plaintext credential fields from model:
   - `backend/src/models/Landlord/Tenant.js`
2. Added hard removal migration (with rollback support):
   - `backend/migrations/20260303000003-remove-tenant-plaintext-db-credentials.cjs`
   - `up`: removes `tenants.db_username` and `tenants.db_password` if present.
   - `down`: restores both columns (nullable string) for rollback compatibility.
3. Updated schema documentation:
   - `docs/database/schema.md` no longer documents `db_username` or `db_password`.
4. Added regression guard test:
   - `backend/tests/tenantCredentialSurface.security.test.js`
   - Verifies `Tenant` model no longer defines `db_username` / `db_password`.
   - Verifies migration exists and explicitly removes both columns.

## Security Outcome
- The application no longer models tenant DB passwords as first-class data.
- A migration now removes plaintext credential columns from landlord schema.
- Test coverage now guards against accidental reintroduction.
