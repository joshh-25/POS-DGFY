# POS E Journal Readiness Grammar Version 0 1

## Purpose

This document defines the internal, versioned e-Journal contract used to build
and test POS BIR readiness for Annex B Item 8. It is a readiness contract, not
a claim that BIR or a provider has accepted this exact field layout.

## Regulatory minimum

RMO No. 24-2023 defines an e-Journal as a daily single `.txt` or standard text
document generated by the POS software. It must reflect the information shown
on principal and supplementary invoices or receipts, adjustment documents such
as returns, voids, cancellations and refunds, and X- and Z-readings. The RMO
also distinguishes this e-Journal from the BIR eSales report and eSales
Journal or Book.

Official source: [BIR RMO No. 24-2023](https://bir-cdn.bir.gov.ph/local/pdf/RMO%20No.%2024-2023.pdf).

The rules below translate that minimum into a deterministic internal fixture
contract. The implementation may not present this contract as an official BIR
or provider grammar without a later external review.

## File contract

- Encoding: UTF-8 without a byte-order mark.
- Line ending: LF (`\\n`). A final LF is required.
- One file represents one tenant, location, terminal, and business date.
- Records are written in ascending `sequence` order and are never rewritten
  after the business date is closed.
- Field order is fixed by record type.
- Values use `key=value` fields separated by `|`.
- The reserved characters `\\`, `|`, carriage return, and line feed are
  escaped as `\\\\`, `\\|`, `\\r`, and `\\n`.
- Monetary values are decimal strings with two fractional digits. Quantities
  use three fractional digits.
- No passwords, access tokens, payment secrets, or raw provider credentials
  may be serialized.

## Record grammar

```text
file       = FILE "|" file_fields LF
document   = DOCUMENT "|" document_fields LF
line       = LINE "|" line_fields LF
payment    = PAYMENT "|" payment_fields LF
adjustment = ADJUSTMENT "|" adjustment_fields LF
reading    = READING "|" reading_fields LF
trailer    = TRAILER "|" trailer_fields LF
record     = file / document / line / payment / adjustment / reading / trailer
field      = key "=" escaped_value
```

All records include `sequence` as their first field after the record type.
The record types and required fields are:

| Record | Required fields |
|---|---|
| `FILE` | `sequence`, `grammar_version`, `business_date`, `tenant_id`, `location_id`, `terminal_id` |
| `DOCUMENT` | `sequence`, `record_id`, `document_type`, `source_transaction_id`, `document_no`, `issued_at`, `gross`, `discount`, `vat`, `net` |
| `LINE` | `sequence`, `record_id`, `document_record_id`, `line_no`, `item_code`, `description`, `quantity`, `unit_price`, `discount`, `vat`, `line_total` |
| `PAYMENT` | `sequence`, `record_id`, `document_record_id`, `method`, `amount`, `reference` |
| `ADJUSTMENT` | `sequence`, `record_id`, `adjustment_type`, `original_transaction_id`, `original_document_no`, `adjustment_document_no`, `occurred_at`, `amount`, `status`, `reason` |
| `READING` | `sequence`, `record_id`, `reading_type`, `reading_no`, `business_date`, `generated_at`, `gross`, `net`, `transaction_count` |
| `TRAILER` | `sequence`, `record_count`, `first_sequence`, `last_sequence`, `content_sha256` |

`document_type` identifies the issued principal or supplementary document.
`adjustment_type` is one of `RETURN`, `VOID`, `CANCELLATION`, or `REFUND` in
the readiness contract. `reading_type` is `X` or `Z`.

`record_count` counts all records before the trailer. `content_sha256` is the
SHA-256 digest of the UTF-8 bytes from the first byte of the `FILE` record
through the LF immediately before the `TRAILER` record. It is not a digest of
the trailer itself.

## Completeness rules

1. Exactly one `FILE` and one `TRAILER` record are required.
2. Every issued receipt or invoice has one `DOCUMENT` record and its related
   `LINE` and `PAYMENT` records.
3. Every adjustment has an `ADJUSTMENT` record linked to its original
   transaction and document number. The original document is never replaced.
4. Every generated X-reading and Z-reading is represented by a `READING`
   record.
5. A provisional or non-fiscal operation is included only when the product
   contract identifies it as a generated document or report; it must not be
   silently converted into a fiscal record.
6. Reprints do not create a second sale; they are represented through the
   existing fiscal event and document identity.
7. The serializer must reject missing required fields, duplicate sequence
   values, duplicate document identities, invalid decimal values, and an
   adjustment without an original-document reference.
