## Finding Description
Models like `Item` and `User` define `deleted_at` fields manually but do *not* enable Sequelize's `paranoid: true` option.

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
- **Current State**: `Item.js` (and others) defines `deleted_at: { type: DataTypes.DATE }` manually.
- **Missing**: The model definition `options` block is missing `paranoid: true`.
- **Result**:
    - `Item.destroy()` performs a HARD DELETE (SQL `DELETE FROM items ...`).
    - The `deleted_at` column is unused unless manually updated (`Item.update({ deleted_at: new Date() })`).
    - `Item.findAll()` does NOT filter out soft-deleted items (if manually "deleted").
- **Impact**: Data loss (if hard delete wasn't intended) or Data Corruption (if manual soft-delete is used but not filtered).

### 2. Proposed Changes
Enable Sequelize Safe Deletes.

#### A. Modify `Item.js`
Add `paranoid: true`.

```javascript
/* Item.js */
}, {
  tableName: 'items',
  timestamps: true,
  createdAt: 'created_at',
  updatedAt: 'updated_at',
  paranoid: true, // Enable Soft Deletes
  deletedAt: 'deleted_at' // Map to snake_case column
});
```

### 3. Verification Plan
1.  Call `Item.destroy({ where: { id: 1 } })`.
2.  Check DB: Row 1 should exist, but `deleted_at` should be NOT NULL.
3.  Call `Item.findAll()`. Row 1 should be missing.
4.  Call `Item.findAll({ paranoid: false })`. Row 1 should appear.

### 4. Risk Assessment
- **Impact**: High (Data Integrity).
- **Complexity**: Low.
