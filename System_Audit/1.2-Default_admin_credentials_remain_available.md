# [OPEN] 1.2 Default Admin Credentials Remain Available

Severity: Critical
Audit area: Authentication, production hardening

## Finding

The admin authentication configuration still contains a default username and a documented default password mapping.

## Evidence

- `backend/src/config/adminAuthConfig.js` defines default admin username `skupervisor`.
- `backend/src/config/adminAuthConfig.js` contains a default password hash fallback.
- `backend/src/modules/adminAuth/README.md` documents that the default hash maps to password `252378`.

## Why This Matters

Default administrative credentials are a critical production risk. Even when intended as a bootstrap convenience, they are easy to leak through documentation, logs, seeded environments, or misconfigured deployments. OWASP ASVS expects administrative authentication to avoid shared/default secrets and to enforce secure credential lifecycle controls.

## Required Remediation

1. Remove production fallback to default admin credentials.
2. Make production startup fail if explicit admin bootstrap credentials are missing or still equal to the documented default.
3. Add a rotation/migration path for existing deployments.
4. Update setup docs so the default is only allowed in local development and cannot silently reach production.

## Acceptance Gates

- Production mode exits non-zero if admin credentials are unset.
- Production mode exits non-zero if admin credentials match the documented default.
- Local development still has an explicit, clearly marked bootstrap path.
- Tests cover production fail-closed behavior.
