# [PARTIAL] 1.2 Default Admin Credentials Remain Available

Severity: Critical
Audit area: Authentication, production hardening

## Re-Baseline Update (2026-08-21)

Source-level remediation is complete for the fail-closed control. Production environment validation now requires explicit admin credentials, rejects the documented bootstrap hash, and runtime account loading rejects the same fallback in `NODE_ENV=production`. Local development retains an explicitly documented bootstrap path. Production credential rotation and deployment evidence remain operational follow-up work, so this finding is not fully resolved.

## Finding

The admin authentication configuration still contains a local-development bootstrap username and password-hash fallback, but production now rejects that fallback.

## Evidence

- `backend/src/config/adminAuthConfig.js` defines default admin username `skupervisor`.
- `backend/src/config/adminAuthConfig.js` contains a default password hash fallback.
- `apps/dgfy-api/src/config/productionEnvValidation.cjs` rejects missing or documented-default production credentials.
- `apps/dgfy-api/tests/adminAuthConfig.test.js` covers local fallback and production fail-closed runtime behavior.

## Why This Matters

Default administrative credentials are a critical production risk. Even when intended as a bootstrap convenience, they are easy to leak through documentation, logs, seeded environments, or misconfigured deployments. OWASP ASVS expects administrative authentication to avoid shared/default secrets and to enforce secure credential lifecycle controls.

## Required Remediation

1. Remove production fallback to default admin credentials.
2. Make production startup fail if explicit admin bootstrap credentials are missing or still equal to the documented default.
3. Add a rotation/migration path for existing deployments.
4. Update setup docs so the default is only allowed in local development and cannot silently reach production.

## Acceptance Gates

- [x] Production mode exits non-zero if admin credentials are unset.
- [x] Production mode exits non-zero if admin credentials match the documented default.
- [x] Local development still has an explicit, clearly marked bootstrap path.
- [x] Tests cover production fail-closed behavior.
- [ ] Rotate credentials and attach production startup evidence for every deployed environment.
