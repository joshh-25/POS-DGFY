# Audit 3.7 - Subscription activation webhook missing premium plan propagation

## Status
Resolved

## Severity
Unspecified

## Root Cause
If subscription-webhook handlers only update `subscription_status` but not `plan`, premium users can remain blocked by access gates that enforce `plan === 'premium'`.

Related consistency risk: cancellation via webhook path missing `cancelled_at` audit timestamp.

## Fix Implemented
1. Activation webhook now sets premium entitlement fields together.
- `handleSubscriptionActivated` sets:
  - `tenant.plan = 'premium'`
  - `tenant.subscription_status = 'active'`
- Also initializes `billing_cycle_anchor` when absent.
- Evidence: `backend/src/controllers/paymentController.js` (around lines 227-245).

2. Cancellation webhook now records cancellation audit time.
- `handleSubscriptionCancelled` sets:
  - `tenant.subscription_status = 'cancelled'`
  - `tenant.cancelled_at = new Date()`
- It intentionally does not immediately downgrade `plan`; scheduler handles downgrade after period/grace rules.
- Evidence: `backend/src/controllers/paymentController.js` (around lines 251-265).

3. Sync path now upgrades plan on ACTIVE, without bypassing grace-period downgrade policy.
- `syncWithPayPal` sets `updatePayload.plan = 'premium'` only when PayPal status is `ACTIVE`.
- Non-ACTIVE statuses do not force immediate downgrade in sync path.
- Evidence: `backend/src/controllers/paymentController.js` (around lines 352-377).

4. Sync/webhook period-end updates are monotonic.
- `current_period_end` is resolved with `maxDate(...)`, preventing backward movement when older timestamps arrive.
- Evidence: `backend/src/controllers/paymentController.js` (around lines 190-193 and 362-367).

## Test Evidence
1. Webhook/sync regression coverage
- `backend/tests/paypalWebhookHandlers.test.js`
- Covers:
  - activation sets plan and active status
  - cancellation sets `cancelled_at` and keeps downgrade ownership with scheduler
  - sync only upgrades plan on `ACTIVE`
  - monotonic period-end behavior

2. Integration cross-check for premium path
- `backend/tests/subscriptionIntegration.test.js`
- Confirms premium entitlement persistence and event contracts on upgrade and registration routes.
