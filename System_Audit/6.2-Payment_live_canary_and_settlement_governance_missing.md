# [OPEN] 6.2 Payment Live Canary and Settlement Governance Missing

Severity: High
Audit area: Payments, billing operations, release evidence

## Finding

The audit found payment safety checks and provider code, but did not find current live canary and settlement reconciliation evidence for payment provider readiness.

## Evidence

- PayMongo webhook fail-open risk is separately documented in finding 1.4.
- PayPal webhook verification fails closed in production when `PAYPAL_WEBHOOK_ID` is missing, while development and test modes can bypass.
- Current audit evidence did not include live provider canary, webhook replay, refund, chargeback, or settlement reconciliation artifacts.

## Why This Matters

Payment integration readiness requires more than local unit behavior. Live or sandbox canary evidence should prove provider callback verification, idempotency, state transitions, settlement reconciliation, refund handling, and failure handling.

## Required Remediation

1. Define payment provider canary scenarios for PayMongo and PayPal.
2. Capture webhook verification, replay rejection, refund, failed payment, and settlement reconciliation evidence.
3. Store canary artifacts with release evidence.
4. Add explicit production enablement gates for each provider.

## Acceptance Gates

- Payment provider canary run is current for the target release.
- Webhook replay and invalid signature tests pass.
- Settlement reconciliation is documented.
- Production payment enablement requires current evidence.
