# [REMEDIATED] 1.4 PayMongo Webhook Signature Verification Can Fail Open

Severity: Critical
Audit area: Payments, webhook integrity
Remediated: 2026-06-03

## Finding

PayMongo webhook verification returned success when the webhook secret was missing.

## Remediation Summary

The live PayMongo verifier now fails closed by default:

1. Missing PayMongo webhook secret returns `false`.
2. Missing PayMongo signature returns `false`.
3. Invalid, stale, or mode-mismatched signatures return `false`.
4. Valid signatures are calculated with HMAC-SHA256 over `timestamp.rawBody` using the documented `Paymongo-Signature` header parts.
5. Unsigned webhook bypass requires `PAYMONGO_ALLOW_UNSIGNED_WEBHOOKS=true`, is blocked in production/live/payment-enabled environments, and is intended only for explicit local non-production testing while `PAYMENTS_ENABLED=false`.
6. PayMongo invalid-signature telemetry is separated as `paymongo_webhook_invalid_signature`.

## Implementation Evidence

Code:

- `backend/src/services/paymongoService.js`
  - Resolves mode-specific webhook secrets via `PAYMONGO_TEST_WEBHOOK_SECRET` / `PAYMONGO_LIVE_WEBHOOK_SECRET`, falling back to `PAYMONGO_WEBHOOK_SECRET`.
  - Rejects missing secrets unless an explicit non-production, payments-disabled unsigned bypass is configured.
  - Verifies `Paymongo-Signature` with `t`, `te`, and `li` fields against the raw request body.
  - Uses constant-time comparison for signature checks.
- `backend/src/modules/payments/usecases/handleWebhookUseCase.js`
  - Keeps verification before webhook-log creation and before payment/subscription mutation.
  - Emits `paymongo_webhook_invalid_signature` for PayMongo signature failures.
- `scripts/deploy.sh`
  - No longer documents missing `PAYMONGO_WEBHOOK_SECRET` as a runtime bypass.
  - States runtime verification rejects unsigned requests unless an explicit non-production bypass is configured.

Tests:

- `backend/tests/paymongoWebhookSignature.test.js`
  - Missing secret rejects in production.
  - Missing secret rejects when `PAYMENTS_ENABLED=true`, even if unsigned bypass is configured.
  - Missing signature rejects with a configured secret.
  - Valid signed raw payload accepts.
  - Tampered signature rejects.
  - Stale timestamp rejects.
  - Live mode uses `li`, not `te`.
  - Explicit unsigned bypass works only for non-production payments-disabled local use.
  - Invalid PayMongo signature is rejected before webhook-log creation or payment mutation.
  - Replayed PayMongo event returns idempotent OK without repeated mutation.

## Residual Risk

1. `PAYMENTS_ENABLED=false` remains the default payment-route safety posture.
2. Live PayMongo delivery, provider dashboard configuration, child-account webhook registration, and settlement correctness still require provider-connected sandbox/production evidence.
3. The commerce-payment code is locally integrated, but production enablement remains gated by `COMMERCE_PAYMENTS_ENABLED`, `COMMERCE_QRPH_ENABLED`, PayMongo credentials, webhook secret verification, migration review, and live canary evidence.
