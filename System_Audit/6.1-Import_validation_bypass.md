# Implementation Plan - 6.1 Critical Validation Bypass in Import Confirmation

## User Feedback
> Make sure this should be COMPREHENSIVELY SECURED. I need you to have security to not let bypasses like these to happen as the database corruption will be the end of this project

## Finding Description
The "Confirm" endpoint blindly trusts the payload sent back by the client after the "Preview" step, allowing malicious modification of validated data.

## Severity
🔴 Critical

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/csvImportService.js` (Lines 372-388):
- The `bulkCreate` method is used for performance when importing items.
- **Code**:
    ```javascript
    const createdItems = await Item.bulkCreate(itemsData, {
        transaction,
        returning: true
    });
    ```
- **Issue**: Sequelize `bulkCreate` **skips** model-level validations by default to maximize speed.
- **Impact**:
    - The `Item` model (Lines 26-40, 61-63 in `Item.js`) has critical validations:
        - `isValidProductType`: Ensures `product_type` logic matches `category`.
        - `current_stock`: `min: 0`.
    - Malicious or malformed CSVs can insert invalid data (e.g., negative stock, mismatched categories) that would be rejected by the API/UI.

### 2. Proposed Changes
Enable validation during bulk creation.

#### A. Modify `csvImportService.js`
Add `validate: true` to the options object.

```javascript
/* csvImportService.js */
const createdItems = await Item.bulkCreate(itemsData, {
    transaction,
    returning: true,
    validate: true // <--- Enable Model Validation
});
```

*Note: If specific hooks are needed (e.g., generating slugs or search vectors), we might also need `individualHooks: true`, but that kills performance. For now, strictly enabling `validate: true` covers the security/integrity operational risk.*

### 3. Verification Plan

#### Automated Test
1.  Prepare CSV with an invalid row: `Category: product`, `Product Type: NULL`.
2.  Call `importCsvData`.
3.  **Expect**: Error (ValidationFailed) or the specific row is rejected (if using ignore/updateOnDuplicate logic, but here it's transaction-wrapped so the batch fails).
4.  **Current Behavior**: Import succeeds, invalid data in persistence.
5.  **Fixed Behavior**: transaction rollback, error returned to user.

### 4. Risk Assessment
- **Impact**: Low (Data Integrity).
- **Performance**: `validate: true` makes `bulkCreate` slower as it instantiates DAO for each row validation. However, for batches of 50 (current setting), this is negligible and worth the integrity guarantee.
