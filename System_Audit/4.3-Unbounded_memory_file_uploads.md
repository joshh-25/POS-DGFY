## Finding Description
The controller uses `fs.readFile` to read entire uploaded files into memory before processing, causing memory spikes.

## Severity
 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/csvImportService.js` (line 15) and `aiService.js`:
- `parseCSV` uses `csv-parse/sync`. This is a blocking operation.
- The `import_csv_data` tool accepts the *entire* CSV content as a string argument (`csv_content`).
- **Vulnerability**: Even with a 10MB upload limit, parsing a 10MB CSV synchronously blocks the Node.js Event Loop, causing a Denial of Service (DoS) for other users. It also causes a large memory spike (String + parsed Objects).

### 2. Proposed Changes
Switch to Streaming Parsing and limit AI context payload.

#### A. Modify `import_csv_data` tool definition
Instead of accepting `csv_content` (File Content) as a string, valid only for tiny snippets, the tool should accept a `file_path` (or `upload_id`) if the file was uploaded via the `upload` endpoint.
However, since the current flow seems to handle raw text from the AI:
1.  **Refactor**: Only allow `csv_content` for small inputs (< 50KB).
2.  **Streaming**: Change `parseCSV` to use `csv-parse` stream or asynchronous `parse` to avoid blocking.

#### B. Implementation Details
In `csvImportService.js`:
```javascript
import { parse } from 'csv-parse'; // Logic change to Async

export const parseCSV = (csvContent) => {
    return new Promise((resolve, reject) => {
        parse(csvContent, { columns: true, ... }, (err, records) => {
            if (err) reject(err);
            else resolve({ success: true, records });
        });
    });
};
```
But for true memory safety with large files, we should process line-by-line, not load all `records` into an array.
Given the AI use case (likely small imports), just making it **Async** is the Critical Step to prevent Event Loop Blocking.

### 3. Verification Plan

#### Automated Test
1.  Create a large mock CSV string (5MB).
2.  Call `parseCSV`.
3.  **Expect**: It yields to the event loop (verify using `setImmediate` check or similar, though hard in unit test).
4.  **Expect**: Successful parse.

#### Manual Verification
1.  Upload a large CSV.
2.  Verify the server remains responsive to other requests during parsing.
