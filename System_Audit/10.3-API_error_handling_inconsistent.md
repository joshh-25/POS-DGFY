# RESOLVED - 10.3 Inconsistent API Error Handling

## Status
Resolved

## Severity
Low

## Root Cause
API error handling was partially centralized but still inconsistent:
- Global 5xx handling was bound to `Layout.jsx` only.
- Public and admin routes could miss global API error toasts.
- `adminService.js` had no global 5xx/network emission path.
- Admin actions still used browser `alert()` while tenant pages used toasts.

## Root Cause
API error handling was partially centralized but still inconsistent:
- Global 5xx handling was bound to `Layout.jsx` only.
- Public and admin routes could miss global API error toasts.
- `adminService.js` had no global 5xx/network emission path.
- Admin actions still used browser `alert()` while tenant pages used toasts.

## Final Implementation
1. Added shared API error normalization and global error event emission:
   - `frontend/src/utils/errorHandler.js`
   - Provides `normalizeApiError(error)` and `emitGlobalApiError({ error, source })`.
2. Added root-level global API error listener:
   - `frontend/src/components/common/GlobalApiErrorListener.jsx`
   - Listens to `api:error` and legacy `api:server-error`.
3. Added toast dedupe utility (5-second message cooldown):
   - `frontend/src/utils/errorToastDedupe.js`
4. Moved global notification mounting to app root:
   - `frontend/src/main.jsx` now mounts one global `<Toaster />` and `<GlobalApiErrorListener />`.
5. Removed layout-scoped global server-error listener:
   - `frontend/Layout.jsx` no longer owns global API error listeners or toaster mounting.
6. Standardized both API clients:
   - `frontend/src/services/api.js` emits global events for 5xx and network/no-response.
   - `frontend/src/services/adminService.js` now does the same.
   - Both support request-level `skipGlobalErrorToast`.
7. Replaced admin action failure `alert()` paths with toast-based UX:
   - `frontend/Pages/admin/TenantManager.jsx`
   - `frontend/Pages/admin/AdminPricing.jsx`
   - Keeps inline error banners for load failures.
8. Reduced duplicate local/global toast risk in representative tenant pages:
   - `frontend/Pages/MobileReceive.jsx`
   - `frontend/Pages/Items.jsx`
   - `frontend/Pages/Suppliers.jsx`
   - `frontend/Pages/JobOrders.jsx`
   - `frontend/Pages/PurchaseOrders.jsx`
   - `frontend/Pages/StockMovements.jsx`
   - These pages now avoid local catch-all toasts for global candidates (5xx/network), while keeping local toasts for permission/domain guidance.

## Event Contract
Canonical event: `api:error`  
Payload:
- `kind`: `'server' | 'network'`
- `status`: `number | null`
- `message`: `string`
- `source`: `'tenant-api' | 'admin-api'`
- `url`: `string | undefined`
- `method`: `string | undefined`
- `timestamp`: ISO string

Legacy compatibility:
- `api:server-error` is still emitted for server errors during migration.
