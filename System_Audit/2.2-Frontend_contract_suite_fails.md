# [REMEDIATED] 2.2 Frontend Contract Suite Fails

Severity: High
Audit area: Frontend correctness, contract testing
Status: Remediated on 2026-06-03

## Finding

The frontend contract suite previously failed across storefront, hospitality, F&B, geo search, purchase order receipt valuation, account header/profile launcher, admin interceptor, and follow behavior.

Current state: remediated. `npm run test:frontend` and the focused `npm run test:frontend:contracts` gate both pass.

## Evidence

Original audit evidence: `npm run test:frontend` failed during audit. Failed suites included:

- `apps/store/src/__tests__/hospitalityStorefront.contract.test.js`
- `apps/store/src/__tests__/storefrontMarkerPreview.test.js`
- `src/features/fnb/__tests__/fnbMode.contract.test.js`
- `apps/store/src/__tests__/geoSearchIntegration.contract.test.js`
- `Components/po/__tests__/POReceiptModal.valuation.integration.test.jsx`
- `apps/store/src/__tests__/storefrontFollow.integration.test.jsx`

Observed failed behavior areas:

- Hospitality storefront mode registration and PMS booking APIs.
- Customer-facing stay controls.
- Storefront marker fallback and duplicate-coordinate marker offsets.
- F&B check context in POS checkout and receipts.
- Discovery search endpoint authority.
- Purchase order receipt variance badge update.
- Storefront follow count and 429 follow error rendering.

Remediation evidence captured on 2026-06-03:

- `npm run test:frontend:contracts` passed 10 files / 33 tests.
- `npm run test:frontend` passed 92 files / 412 tests with the deterministic one-worker frontend runner.
- `npm --prefix frontend run lint` passed.
- `npm --prefix frontend run build:all` passed.

Changed implementation/tests:

- `frontend/src/services/__tests__/adminService.interceptor.test.js` now authenticates through the memory-token admin login contract instead of seeding `sessionStorage`.
- `frontend/apps/store/src/storefrontMarkerPreview.js` preserves exact marker coordinates for duplicate locations and uses the governed `Storefront location` fallback label.
- `frontend/apps/store/src/StorefrontApp.jsx` aborts stale discovery requests, mounts `HospitalityBookingPanel` for hospitality storefront mode, and exposes formatted follow counts.
- `frontend/apps/store/src/Components/storefront/hero/StorefrontHeroNameCluster.jsx` renders explicit follow errors in the storefront hero.
- `frontend/apps/store/src/__tests__/hospitalityStorefront.contract.test.js`, `frontend/src/features/fnb/__tests__/fnbMode.contract.test.js`, and `frontend/apps/store/src/__tests__/fnbStorefront.contract.test.js` were reconciled to current source boundaries while preserving the governed behavior contracts.
- `scripts/gate-release-local.js` now runs the root `test:frontend:contracts` gate as part of local release readiness.

## Why This Matters

These tests cover user-facing and contract-sensitive behavior. A production release with failing contract tests can regress storefront discovery, hospitality mode, F&B POS receipts, inventory valuation display, and customer engagement flows.

## Required Remediation

Completed:

1. Triaged each failing suite by current storefront, hospitality, F&B, admin-auth, discovery, follow, and PO contract owner.
2. Fixed implementation where governed behavior had drifted.
3. Updated brittle source-string tests only where the implementation had moved to a different owned module.
4. Re-ran `npm run test:frontend`.
5. Added release-gate linkage through `npm run test:frontend:contracts`.

## Acceptance Gates

- `npm run test:frontend` passes.
- `npm run test:frontend:contracts` passes.
- Storefront, hospitality, F&B, geo, PO, admin interceptor, discovery account, profile launcher, and follow flows have current green evidence.
- ADR update was not required because this remediation restored existing governed contracts rather than introducing a new architecture or product contract.
