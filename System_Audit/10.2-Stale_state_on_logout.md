## Problem
In a SPA session, in-memory client state can survive route changes. If logout only redirects to `/login` without a full client cleanup, the next user on the same browser can briefly see stale state from the previous user.

## Root Cause (Verified)
- Logout behavior was distributed across multiple call sites.
- Session artifacts were not guaranteed to be cleared in one canonical path.
- Cache scope isolation needed explicit session epoch invalidation to prevent stale reads after user switch.

## Implementation
1. Centralized client session cleanup logic.
- Added `frontend/src/services/sessionCleanup.js` to clear auth tokens, tenant token, transient auth state, and broadcast logout/session-expiry events safely.

2. Unified logout + cross-tab expiry behavior.
- Updated `frontend/src/services/authService.js` and `frontend/src/services/api.js` so both explicit logout and session-expired paths use the same hard cleanup semantics.
- Cross-tab messages (`auth:logout`, `session-expired`) now force immediate local cleanup and login redirect.

3. Reset state and caches deterministically.
- Updated `frontend/src/store/useStore.js` to use a canonical initial-state reset path.
- Added session-aware cache invalidation:
  - `frontend/src/services/cacheRegistry.js`
  - `frontend/src/hooks/useItems.js` now scopes cache with `authEpoch` + `companyToken`.

4. Defensive cleanup at login entry.
- `frontend/Pages/Login.jsx` performs a non-broadcast local cleanup on mount to prevent stale carry-over when users revisit login directly.
