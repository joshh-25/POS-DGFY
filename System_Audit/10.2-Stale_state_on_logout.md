# ? RESOLVED - 10.2 Stale State on Logout

**Severity**: 🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `frontend/Layout.jsx` and `src/services/authService.js`:
- Logout clears `localStorage` and dispatches `auth:logout`.
- `Layout.jsx` uses `navigate('/login')` (Client-side routing, no page reload).
- `PermissionContext.jsx` listens to `auth:logout` and resets.
- **Vulnerability**: `useStore.js` (Zustand global store) does **NOT** listen to `auth:logout` or expose a global reset mechanism that `Layout.jsx` calls.
- **Result**: `items`, `suppliers`, `purchaseOrders`, `dashboardStats`, etc. remain in memory after logout.
- **Scenario**:
    - Admin logs in, views "Secret Project Job Order".
    - Admin logs out.
    - User B logs in (on same tab).
    - User B navigates to Job Orders.
    - If `JobOrders.jsx` logic is "if (jobOrders.length > 0) show them else fetch", User B sees Admin's list for a split second (or longer) before the new fetch overwrites it.

### 2. Proposed Changes
Implement a global store reset.

#### A. Modify `useStore.js`
Add a `reset()` action that resets all slices to initial state.

```javascript
/* useStore.js */
const initialState = {
  items: [],
  // ... all initial values ...
};

const useStore = create((set) => ({
  ...initialState,
  // ... setters ...
  reset: () => set(initialState)
}));
```

#### B. Modify `Layout.jsx`
Call `reset()` on logout.

```javascript
/* Layout.jsx */
const { reset } = useStore();

const handleLogout = async () => {
    await logout();
    reset(); // Clear global state
    navigate('/login');
};
```

### 3. Verification Plan

#### Manual Verification
1.  Login as User A. Load Items.
2.  Open Console, execute `useStore.getState().items`. Usage/View it.
3.  Logout.
4.  Check `useStore.getState().items`.
5.  **Expect**: Empty Array `[]`.
6.  **Current Behavior**: Still has User A's items.
