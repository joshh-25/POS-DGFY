# Implementation Plan - 11.1 Database Credentials Stored in Plain Text

## User Feedback
(Pending User Feedback - Critical Security Issue)

## Finding Description
The `Tenant` model in the landlord database stores the `db_password` for each tenant's database connection in plain text.

## Severity
🔴 Critical

## Proposed Plan

### 1. Root Cause Analysis
- **Current State**: Database credentials (`DB_USER`, `DB_PASSWORD`) are stored in `.env` files.
- **Risk**:
    - `.env` files might be accidentally committed to git (though `.gitignore` exists, accidents happen).
    - Plaintext credentials on disk on the server.
    - No rotation mechanism.
- **Standard**: For high-security applications (like Inventory/Financials), credentials should be injected via a Secret Manager (AWS Secrets Manager, Vault) at runtime, or encrypted.

### 2. Proposed Changes
Migrate to a Secrets Manager or Environment Variable Injection during CI/CD.

#### A. Immediate: Secure .env permissions
Ensure `.env` is `600` (read/write by owner only) on the server.

#### B. Long-term: Cloud Secret Manager
1. Update `config/database.js` to fetch secrets from AWS/GCP/Azure Secret Manager on startup if `NODE_ENV === 'production'`.

```javascript
/* config/database.js */
if (process.env.USE_SECRET_MANAGER) {
   const secrets = await fetchSecrets();
   process.env.DB_PASSWORD = secrets.DB_PASSWORD;
}
```

### 3. Verification Plan
1.  Check file permissions on server: `ls -la .env`.
2.  Verify `.gitignore` includes `.env`.

### 4. Risk Assessment
- **Impact**: Low (Best Practice).
- **Complexity**: High (Infrastructure change).
