# Implementation Plan - 4.2 Permission checks suffer from TOCTOU vulnerability

## User Feedback
> Make a robust plan to prevent this from happening

## Finding Description
Permissions are checked only when the tool call is generated. When the user confirms the action later, the system validates ownership but not role/permission.

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/aiService.js`, the `executeConfirmedAction` function (lines 737-775) processes a pending action after user confirmation.
- **Current Check**: `if (pendingAction.user_id !== user.user_id) ...`
- **Missing Check**: It does **not** re-verify if the user still has the `requiredRole` or `requiredPermission` for the tool.
- **Vulnerability**:
    1.  User asks to "Delete Item".
    2.  System checks permissions -> OK. Generates Confirmation.
    3.  Admin revokes User's "Delete" permission.
    4.  User clicks "Confirm".
    5.  `executeConfirmedAction` runs. It checks ID -> OK. Executes tool.
    6.  **Result**: Unauthorized Action.

### 2. Proposed Changes
Re-validate permissions in `executeConfirmedAction`.

#### A. Modify `executeConfirmedAction` in `aiService.js`
1.  Retrieve the tool definition.
2.  Perform the same RBAC and PBAC checks as `handleToolCalls`.

```javascript
/* In executeConfirmedAction */
const tool = getToolByName(pendingAction.toolName);

// 1. Re-check Role Permission
if (tool && tool.requiredRole && !hasPermission(user.role, tool.requiredRole)) {
    throw new Error(`Permission denied: You no longer have the required role to execute ${pendingAction.toolName}`);
}

// 2. Re-check Granular Permission
if (tool && tool.requiredPermission && !hasGranularPermission(user, tool.requiredPermission)) {
    throw new Error(`Permission denied: You no longer have the required permission to execute ${pendingAction.toolName}`);
}

// Proceed to execution...
const result = await toolExecutor.execute(...);
```

### 3. Verification Plan

#### Automated Test
1.  Mock `user` with `role: 'admin'`.
2.  Generate a confirmation for a sensitive tool.
3.  Change mock `user` role to `staff` (or revoke permission).
4.  Call `executeConfirmedAction`.
5.  **Expect**: Error "Permission denied".

#### Manual Verification
1.  As Admin, ask AI to "Delete Item 123".
2.  Wait at the Confirmation Card.
3.  In another tab, downgrade the Admin user to Staff (or remove delete permission).
4.  Click "Confirm" on the original tab.
5.  **Expect**: Error message in the UI.

### 4. Risk Assessment
- **Impact**: Medium (Security hardening).
- **Mitigation**: Minimal risk of regression, just standard auth checks.
