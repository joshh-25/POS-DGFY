# [OPEN] 3.1 StorefrontApp Monolith Exceeds Codegen Threshold

Severity: High
Audit area: Frontend performance, maintainability, testability

## Finding

`frontend/apps/store/src/StorefrontApp.jsx` is large enough that Babel deoptimized code generation during frontend checks.

## Evidence

- Frontend lint output included Babel's message that code generation styling was deoptimized because `StorefrontApp.jsx` exceeds 500KB.
- Frontend lint also produced many warnings in the same storefront surface, including unused variables and hook dependency warnings.

## Why This Matters

A storefront monolith above Babel's 500KB deoptimization threshold is hard to test, slow to transform, and likely to accumulate hidden coupling. This directly affects user-facing storefront workflows and makes contract failures harder to isolate.

## Required Remediation

1. Split `StorefrontApp.jsx` by stable feature boundaries.
2. Extract hooks, API adapters, map behavior, discovery state, hospitality flows, follow behavior, and marker rendering into focused modules.
3. Eliminate unused state and hook dependency warnings.
4. Keep user-facing behavior contract-covered during extraction.

## Acceptance Gates

- Babel deoptimization warning is gone.
- Storefront contract tests pass.
- Storefront modules have clear ownership and focused tests.
- No new architecture or import-boundary exceptions are introduced.
