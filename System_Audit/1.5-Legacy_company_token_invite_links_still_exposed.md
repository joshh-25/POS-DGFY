# [REMEDIATED] 1.5 Legacy Company Token Invite Links Still Exposed

Severity: High
Audit area: Tenant onboarding, invitation security, ADR alignment
Remediated: 2026-06-03

## Finding

The frontend previously built an invitation/join URL that included `companyInfo.company_token`, despite ADR 0015 defining registry-backed token-only tenant user invitations.

## Remediation Summary

The application no longer generates first-party company-token invite links:

1. Settings no longer renders or copies `/register?token=<company_token>` as a company join link.
2. Settings company-info no longer returns `registration_link`.
3. The AI `get_company_join_link` tool is retired and removed from generated capability docs.
4. Invitation emails build `/accept-invite?token=<invitation_token>` links only.
5. The invitation acceptance page ignores legacy `company` and `companyToken` URL parameters for registry-backed validation, OTP request, and account acceptance.
6. User invitation create/resend/manual-link recovery remains registry-backed and token-only.

## Residual Risk

1. Authenticated Settings still displays and allows copying the tenant `company_token` as tenant context for authorized master-admin workflows. It is no longer presented as an invitation URL.
2. ADR 0015 still permits already-issued tenant-local legacy `?company=` links until expiry. This remediation does not create new legacy links.
3. Direct `/register?token=<company_token>` registration remains a separate legacy tenant user registration path and should be evaluated independently if the product intends to retire direct company-token registration entirely.
