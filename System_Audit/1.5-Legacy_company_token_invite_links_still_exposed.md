# [OPEN] 1.5 Legacy Company Token Invite Links Still Exposed

Severity: High
Audit area: Tenant onboarding, invitation security, ADR alignment

## Finding

The frontend still builds an invitation URL that includes `companyInfo.company_token`, despite the repository direction that tenant user invitations should use token-only invite links backed by the invitation registry.

## Evidence

- `frontend/Pages/Settings.jsx` builds `/register?token=${companyInfo.company_token}`.
- `docs/architecture/adr/0015-tenant-user-invitation-registry.md` defines the tenant user invitation registry and token-only invitation contract.

## Why This Matters

Company tokens in URLs can leak through browser history, logs, screenshots, referrers, support tickets, and analytics. Tenant onboarding should use scoped, expiring invitation tokens, not reusable company identity material.

## Required Remediation

1. Remove company token invite URLs from user-facing settings.
2. Generate scoped invitation registry records for user invitations.
3. Make invite tokens single-purpose, expiring, and auditable.
4. Add regression tests proving generated links do not contain company tokens.
5. Provide a migration path for any existing legacy invite flow.

## Acceptance Gates

- No frontend route constructs an invite link using `company_token`.
- Invite link generation is covered by tests.
- ADR 0015 remains the authoritative contract.
- Old invite paths either redirect safely or are explicitly retired.
