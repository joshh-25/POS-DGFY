# ✅ RESOLVED — 2.6 `tenantModelFactory` inherits from default models blindly

> **Status**: Implemented & verified against real MySQL (2026-02-17)
> **Branch**: `scaling`

## Finding Description
The factory assumes `defaultModels[name]` exists. If a model is removed from `defaultModels` but kept in the `modelNames` array, this will throw a runtime error.

## Severity
🟢 Low

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/utils/tenantModelFactory.js`:
1.  **Blind Option Copying** (Line 35): `{ ...originalModel.options, sequelize }`.
    - **Risk**: If the source model (e.g., `User.js`) defines hooks (e.g., `beforeCreate`) that rely on global imports (like `import db from '../models/index.js'`), the tenant model will execute those same hooks. Instead of interacting with the *tenant* transaction/context, the hook will interact with the *landlord* DB. This is "Scope Contamination".
    - **Example**: A hook checking `SystemSetting.findOne()` would check the *Landlord* settings, not the Tenant's.
2.  **Association Duplication** (Lines 42-200): The file manually hardcodes every single `hasMany`, `belongsTo`, etc.
    - **Risk**: Any change to `models/index.js` (e.g., adding a relation) must be copy-pasted here. This violates DRY and leads to "Association Drift" where tenant models behave differently from the core design.

### 2. Proposed Changes
Refactor the Factory to be **Dynamic** and **Safe**.

#### A. Dynamic Association Mapper
Instead of hardcoding associations, iterate over the source model's association map and recreate them.

```javascript
// Iterate all models
Object.keys(defaultModels).forEach(modelName => {
    const SourceModel = defaultModels[modelName];
    const TargetModel = models[modelName];
    
    // Iterate associations: { user: BelongsTo, items: HasMany, ... }
    Object.values(SourceModel.associations).forEach(assoc => {
        const targetAssocName = assoc.as; // e.g. 'items'
        const targetModelName = assoc.target.name; // e.g. 'Item'
        const sourceLogic = assoc.source.name; // e.g. 'ItemFolder'
        
        // Reconstruct the relationship
        const TargetAssociatedModel = models[targetModelName];
        
        if (TargetAssociatedModel) {
            // e.g. TargetModel.hasMany(TargetAssociatedModel, { ...options })
            // We need to extract the type (HasMany, BelongsTo) and options (foreignKey, as, etc.)
            
            // This requires mapping Sequelize Association Types or utilizing `assoc.associationType`
            if (assoc.associationType === 'HasMany') {
                TargetModel.hasMany(TargetAssociatedModel, {
                    foreignKey: assoc.foreignKey,
                    as: assoc.as,
                    // ... other options
                });
            } else if (assoc.associationType === 'BelongsTo') {
                TargetModel.belongsTo(TargetAssociatedModel, {
                    foreignKey: assoc.foreignKey,
                    as: assoc.as,
                     // ...
                });
            }
            // ... handle HasOne, BelongsToMany
        }
    });
});
```

#### B. Safe Option/Hook Cloning
Stop blindly copying options.
1.  Extract `rawAttributes`.
2.  Extract *safe* options (tableName, timestamps, strict).
3.  **Hooks**: Explicitly decide policy.
    - **Option 1**: Strip all hooks (Safest, but loses functionality).
    - **Option 2**: Re-bind hooks? (Hard in JS).
    - **Option 3 (Recommended)**: Move hooks to a "Service Utility" that accepts the `transaction` and `models` as arguments, ensuring they are context-aware, rather than relying on closure imports.
    - **Intermediate Fix**: For now, shallow copy is acceptable *if and only if* we audit all models to ensure no hooks use global state.

## Implementation Notes (2026-02-17)

All three parts were implemented in a single file change to `backend/src/utils/tenantModelFactory.js`.

### Part A — Safe Hook Cloning

`hooks` is destructured out of `originalModel.options` before the spread, so `sequelize.define()` receives no hooks and `_setupHooks({})` runs clean. Hooks are then re-applied via `model.addHook()`.

**Critical discovery during real-MySQL testing**: Sequelize expands proxy hooks at define-time, meaning `options.hooks` already contains `{ beforeSave: [fn], beforeCreate: [fn], beforeUpdate: [fn] }` — all pointing to the same function. Naively iterating all three keys and calling `addHook` caused **double registration** on `beforeCreate`/`beforeUpdate` (the hook would fire twice on every save). The fix filters to **canonical hooks only** (non-proxy-target keys) by skipping `beforeCreate`, `beforeUpdate`, `afterCreate`, `afterUpdate` when those are covered by a proxy hook (`beforeSave`/`afterSave`) also present in the same model.

Hook counts verified on real MySQL to exactly match the source model (1 registration each for `beforeSave`, `beforeCreate`, `beforeUpdate`). The `FIFOBatch.beforeSave` expiry-date validator fires correctly and nullifies invalid dates.

### Part B — Dynamic Association Mapper

Replaced ~160 lines of hardcoded associations (lines 65–210) with a dynamic loop over `Object.keys(defaultModels)`. For each source model in `defaultModels`, the loop reads `sourceModel.associations` and recreates each association on the corresponding tenant clone using `assocOptions = { foreignKey: assoc.foreignKey, as: assoc.as }`.

Verified on real MySQL:
- `assoc.foreignKey` is always a plain string (not an object) in this Sequelize version.
- All 4 association types (`HasMany`, `HasOne`, `BelongsTo`, `BelongsToMany`) handled.
- Self-referential `ItemFolder → ItemFolder` (parent/children) works correctly.
- PO double alias (`lineItems` + `items`) preserved — both exist as separate entries in `PurchaseOrder.associations`.
- Landlord-only models (`Tenant`, `Payment`, etc.) silently skipped — not present in `models`.
- Real nested include queries (`PO → Supplier → LineItem → Item`, `JO → Ingredients → Item`) executed and returned correct data.

### Part C — Missing Model Warning

`logger.warn()` fires if a name in `modelNames` has no matching entry in `defaultModels`.
