#  RESOLVED - Implementation Summary - 8.3 Temp File Leak on Server Restart

## Status
Resolved

## Severity
Low

## Root Cause
`tempFileService` relies on `setTimeout` for cleanup, so files remain if the server restarts before the timeout.

## Fix Implemented
### Phase 1 (Previously Applied)
**CSV Controllers**  `csvImportController.js` and `supplierCSVController.js` now read uploaded files via `fs.readFile` (not `.buffer`) and immediately delete them in a `finally` block.

### Phase 2 (Applied 2026-03-03)
Three additional hardening fixes:

1. **AI Controller file leak**  `aiController.js` `chat` handler accepted up to 5 files via `upload.array('files', 5)` but never deleted them. Added `uploadedPaths` tracking + `finally { fs.unlink }` cleanup.

2. **Startup cleanup**  `cleanupService.js` now runs `cleanupTempFiles()` immediately at init, purging any files leaked before a crash/restart (previously waited up to 15 min for first cron tick).

3. **File filter enforcement**  `uploadConfig.js` `fileFilter` had a dead-code bug where both branches called `cb(null, true)`, accepting all file types. Now properly rejects unsupported MIME types with a `MulterError`.

### Files Changed
- `backend/src/controllers/aiController.js`  finally-block file cleanup
- `backend/src/services/cleanupService.js`  immediate cleanup on init
- `backend/src/config/uploadConfig.js`  enforce file type allowlist

### Verification
- All three files pass `node --check` syntax validation
- Existing `fileEncapsulation.test.js` tests continue to pass structure
- Manual verification: Upload via AI chat  check `uploads/temp/`  file is gone
