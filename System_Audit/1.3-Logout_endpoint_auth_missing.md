# Implementation Plan - 1.3 `logout` endpoint does not require authentication
**Status: ✅ Fixed**

## User Feedback
> I need you to reassure that if we will implement a fix for this, the graceful handling will still be a perfect fit once we fix the incosistent security practices

## Finding Description
The `POST /auth/logout` route has no `authenticate` middleware. Any request (even without a token) can hit this endpoint.

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
The `POST /auth/logout` endpoint defined in `backend/src/routes/auth.js` does not use the `authenticate` middleware. It relies on `authController.logout` manually extracting the token from the header.

The `authService.blacklistToken` function uses `jwt.decode(token)` which **does not verify the signature**.
**Vulnerability**: An attacker can generate millions of fake JWTs with valid JSON structure and future expiration dates, send them to `/logout`, and fill the Redis instance with garbage keys, causing a Denial of Service (DoS).

### 2. Proposed Changes
We must ensure that only **valid, signed tokens** issued by our server can be blacklisted.

#### A. Apply Middleware to Route in `backend/src/routes/auth.js`
- Add `authenticate` middleware to the logout route.
- This ensures that `req.headers.authorization` contains a valid, signed token before the controller executes.

```javascript
// BEFORE
router.post('/logout', authController.logout);

// AFTER
import { authenticate } from '../middleware/auth.js';
// ...
router.post('/logout', authenticate, authController.logout);
```

#### B. Update Controller in `backend/src/controllers/authController.js`
- The `authenticate` middleware guarantees the token is valid or returns 401.
- We can simplify the controller logic since we know the token is present and valid.

### 3. Verification Plan

#### Automated Test
1.  Generate a fake JWT (random signature).
2.  Send `POST /auth/logout` with this fake token.
3.  **Expect**: 401 Unauthorized (because `authenticate` fails signature check). Redis is NOT touched.

#### Manual Verification
1.  Login to get a valid token.
2.  Call `/logout` -> **Expect**: 200 OK.
3.  Call `/logout` again -> **Expect**: 401 Unauthorized (because it's now blacklisted/revoked).

### 4. Risk Assessment
- **Impact**: Medium. Changes API behavior: clients sending invalid tokens to logout will now get 401 instead of 200. This is standard secure behavior.
- **Mitigation**: Frontend should clear local storage regardless of the API response, so user experience remains consistent.
