# Implementation Plan - 5.3 Void logic silently ignores missing batches

## User Feedback
> Plan out to remove the discrepancy of sums of batches and global stock. THey should always have integrity and correct logic calculation

## Finding Description
When reversing a movement, if a referenced batch is missing, the system silently skips the batch update but restores the global stock, causing discrepancies.

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/stockMovementService.js`, the `voidMovement` function handles the reversal of stock movements.
- **Scenario**: Voiding a "Purchase Receipt" (or any addition).
- **Code (Lines 525-534)**:
    ```javascript
    if (quantity > 0 && reverseQuantity < 0 && batch_id) {
        const batch = await FIFOBatch.findByPk(batch_id, { transaction });
        if (batch) {
            // "Consume" the batch to hide it
            const newConsumed = parseFloat(batch.quantity_consumed) + parseFloat(quantity);
            await batch.update({
                quantity_consumed: Math.min(newConsumed, parseFloat(batch.quantity))
            }, { transaction });
        }
    }
    ```
- **Vulnerability**: It does **not** check if the batch has *already* been used by other movements (Sales, Production).
- **Result**: If Batch A (100 qty) has 50 qty consumed by a Job Order, and the user voids the Receipt for Batch A:
    1.  The Batch is marked 100/100 consumed (invisible).
    2.  Stock count reduces by 100.
    3.  The Job Order *still exists* and references Batch A.
    4.  We have consumed stock that "never existed".
    5.  Depending on current stock, `current_stock` might go negative (checked at lines 487, but might pass if other stock exists).

### 2. Proposed Changes
Prevent voiding of "Active" batches that have downstream dependencies.

#### A. Modify `voidMovement` in `stockMovementService.js`
When voiding an *addition* (quantity > 0), check the batch's `quantity_consumed`.

```javascript
// Inside voidMovement
if (quantity > 0 && reverseQuantity < 0 && batch_id) {
    const batch = await FIFOBatch.findByPk(batch_id, { transaction });
    if (batch) {
        const consumedCheck = parseFloat(batch.quantity_consumed);
        // Allow a tiny float tolerance if needed, or strict 0
        if (consumedCheck > 0) {
            throw new Error(`Cannot void this movement: The associated batch has already been used (Consumed: ${consumedCheck}). Please revert downstream usage first.`);
        }
        
        // If unused, we can either Delete the batch or Mark as Voided
        // Current logic maxing out quantity_consumed is 'okay' for hiding, 
        // but maybe marking keys as 'voided' is cleaner? 
        // For now, minimal change: Just enforce the check.
        
        // ... existing update logic ...
    }
}
```

### 4. Risk Assessment
- **Impact**: Medium (Data Integrity).
- **Mitigation**: Users might be annoyed they can't "Undo" a mistake if auto-consumption grabbed it instantly. They will need to void the consumption first. This is correct accounting behavior.
