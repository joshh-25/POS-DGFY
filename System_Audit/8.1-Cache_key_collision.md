# ? RESOLVED - Implementation Plan - 8.1 Cache Key Collision Risk (Multi-Tenancy)

## User Feedback
> Prevent Data leaks so that other companies will not see each other's data and keep their own data integreity

## Finding Description
The `cacheService` provides raw access to Redis without automatically namespacing keys by `tenantId`.

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/cacheService.js`:
- The service exports `get(key)` and `set(key)` which pass the string directly to Redis.
- **Vulnerability**: There is no enforcement of Tenant ID namespacing.
- **Scenario**:
    - Developer A writes a new feature: "Cache user profile by ID".
    - `cacheService.set('user_123', profileData)`.
    - Tenant A has User 123. Tenant B has User 123.
    - Tenant B logs in, hits the cache, and sees Tenant A's profile data.
- **Current Status**: Only `authService` uses it (`blacklist:token:...`), which is safe by coincidence (tokens are globally unique).
- **Risk**: High latency bomb (future collision) waiting to happen.

### 2. Proposed Changes
Enforce Tenant Namespacing in `cacheService`.

#### A. Modify `cacheService.js`
1.  Integrate `dbStore` (which holds `tenantId` in ALS).
2.  Prefix all keys with `tenant:{id}:` unless explicitly opted out (e.g. for global tokens).

```javascript
/* cacheService.js */
import dbStore from '../utils/dbStore.js';

const getScopedKey = (key) => {
    // If key explicitly requests global scope (e.g. 'global:xxx'), allow it.
    if (key.startsWith('global:') || key.startsWith('blacklist:')) return key;

    const store = dbStore.getStore();
    const tenantId = store?.tenantId;
    
    if (tenantId) {
        return `tenant:${tenantId}:${key}`;
    }
    // Fallback? Or Warn?
    return key; 
};

export const set = async (key, value, ttl) => {
    const scopedKey = getScopedKey(key);
    // ... proceed ...
};
```

### 3. Verification Plan

#### Automated Test
1.  Mock `dbStore.getStore` to return `tenantId: 1`.
2.  Call `cacheService.set('user_1')`.
3.  **Expect**: Redis receives `tenant:1:user_1`.
4.  Mock `tenantId: 2`.
5.  Call `cacheService.set('user_1')`.
6.  **Expect**: Redis receives `tenant:2:user_1`.

### 4. Risk Assessment
- **Impact**: Low (Currently). High (Future-proofing).
- **Regression**: Existing `blacklist:` keys will continue to work (via exemption).
