## User Feedback
> Make sure that the integrity of their billing is properly addressed

## Finding Description
Subscription extension simply adds 30 days to `now`, ignoring the actual billing cycle anchor or the previous expiry date.

## Severity
🟢 Low

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/controllers/paymentController.js` (lines 121-122):
```javascript
const newPeriodEnd = new Date();
newPeriodEnd.setDate(newPeriodEnd.getDate() + 30);
```
- **Issue**: This "Simplified Logic" adds a fixed 30 days.
- **Result**: The billing date drifts.
    - Jan 31 + 30 days = March 2 (not Feb 28/29).
    - Long term, the user's billing day shifts from the 1st of the month to the 2nd, 3rd, etc., confusing accounting.
- **Proper Logic**: Monthly subscriptions should generally try to stick to the same "Day of Month" (Anchor Date).

### 2. Proposed Changes
Respect the Payment Provider's (PayPal) authoritative schedule.

#### A. Modify `handlePaymentCompleted`
Use `next_billing_date` from the PayPal webhook resource if available.

```javascript
// In handlePaymentCompleted(resource)
let nextBillingDate;

if (resource.next_billing_date) {
    nextBillingDate = new Date(resource.next_billing_date);
} else if (resource.billing_info && resource.billing_info.next_billing_time) {
    nextBillingDate = new Date(resource.billing_info.next_billing_time);
} else {
    // Fallback: Add 1 Calendar Month, not 30 days
    const now = new Date();
    nextBillingDate = new Date(now);
    nextBillingDate.setMonth(nextBillingDate.getMonth() + 1);
    // Handle overflow (e.g. Jan 31 -> Feb 28)
    if (nextBillingDate.getDate() !== now.getDate()) {
        nextBillingDate.setDate(0); // Set to last day of previous month
    }
}

tenant.current_period_end = nextBillingDate;
```
