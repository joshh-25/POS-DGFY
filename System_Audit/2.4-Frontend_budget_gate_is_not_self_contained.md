Root-cause evidence found during remediation:

- The previous script scanned whichever `dist-apps/*/assets` directories existed and fell back to `frontend/dist/assets`, so partial or legacy artifacts could become the budget input.
- The previous script did not build the apps, did not prove route chunk freshness, and did not write a budget report that the release gate could preserve.
- The local release gate invoked `npm run check:frontend-budgets` without a release-owned report path.

## Why This Matters

Performance gates must be deterministic and actionable. If a gate depends on build artifacts, the release pipeline should either build them as part of the gate or require and verify a prior build step explicitly.

## Remediation Completed

1. The default budget gate now owns `npm --prefix frontend run build:all`.
2. Required artifacts are fixed to `dist-apps/skupervisor/assets`, `dist-apps/pos/assets`, and `dist-apps/store/assets`; missing app outputs fail clearly.
3. Budgeted route chunks must be newer than the build-start freshness floor.
4. Explicit prebuilt mode requires `--skip-build --built-after <timestamp>` so stale artifacts cannot pass silently.
5. The budget report is written as JSON and is wired into the local release gate artifact paths.
6. `docs/testing/README.md` documents the build ownership, prebuilt contract, freshness proof, and report paths.

## Acceptance Gates

- Passed: Frontend budget gate is reproducible without relying on a prior manual build because it owns `build:all` by default.
- Passed: Missing or stale built assets produce clear precondition/freshness failures in the focused test coverage.
- Passed: Bundle/performance budget expectations and report paths are documented in `docs/testing/README.md`.
- Passed: `npm run gate:release:local` passed for target SHA `be59a6b55f4d6367acd124729b43fa4ee579d09b` after the self-contained budget contract was updated.

## Residual Risks

- The aggregate gate still emits a non-blocking Node deprecation warning from `scripts/gate-release-local.js` using Windows `shell: true`; it did not affect the verdict, but it is worth hardening in a future release-tooling cleanup.
- Vite still reports large lazy map chunks and stale Browserslist data as warnings. The budget gate keeps MapLibre isolated and under the dedicated cap, but production performance should still be watched with browser/runtime evidence.
