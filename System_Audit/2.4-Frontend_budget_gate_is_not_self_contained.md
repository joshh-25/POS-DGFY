# [OPEN] 2.4 Frontend Budget Gate Is Not Self-Contained

Severity: Medium
Audit area: Release automation, frontend performance

## Finding

The frontend budget gate is not fully self-contained and currently fails after a successful `build:all` because several POS route chunks exceed their configured limits.

## Evidence

- Initial audit evidence showed `npm run check:frontend-budgets` failing when built assets were missing.
- Follow-up evidence after `npm --prefix frontend run build:all` showed built assets were available, but `npm run gate:release:local` still failed `frontend.budgets` because:
  - `POSCheckoutTerminal-B8zETmkd.js` was `65.14KB` against a `64KB` limit.
  - `POSCheckoutTerminal-Dg-xnDpf.js` was `67.2KB` against a `67KB` limit.
  - `SkupervisorPOSPage-B2VUZLx6.js` was `58.05KB` against a `58KB` limit.

## Why This Matters

Performance gates must be deterministic and actionable. If a gate depends on build artifacts, the release pipeline should either build them as part of the gate or require and verify a prior build step explicitly. When artifacts exist, over-budget chunks must be treated as a real release decision rather than conflated with missing-artifact setup.

## Required Remediation

1. Decide whether the budget gate owns the frontend build or validates a required prebuilt artifact.
2. Reduce the over-budget POS chunks or update the documented budget thresholds with justification and owner approval.
3. Encode the build/prebuilt-artifact decision in the release gate.
4. Add a clear artifact path and freshness check.
5. Preserve budget output in release artifacts.

## Acceptance Gates

- Frontend budget gate is reproducible from a clean checkout.
- Missing or stale built assets produce a clear precondition failure before release verdict calculation.
- Core Web Vitals or equivalent bundle/performance budgets are documented.
