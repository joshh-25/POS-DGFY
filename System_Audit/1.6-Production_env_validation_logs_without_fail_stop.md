# [REMEDIATED] 1.6 Production Env Validation Logs Without Fail Stop

Severity: High
Audit area: Production hardening, configuration safety

## Finding

Production environment validation logged missing required variables without forcing the application to exit.

Status: Remediated on 2026-06-03.

## Evidence

- `backend/src/config/productionEnvValidation.cjs` now owns the centralized production environment validation contract.
- `backend/src/server.js` calls the centralized validator before CORS setup, database connection, scheduler startup, or `app.listen`.
- Production validation exits non-zero when required values are missing or invalid.
- Non-production validation remains warning-only.
- `scripts/check-hosting-profile.js` now reuses the same validator for shared/VPS preflight.
- `scripts/check-production-env-fixtures.js` validates CI/local fixture coverage for shared, VPS, and payment-enabled PayMongo production env shapes.
- `scripts/gate-release-local.js` now includes `npm run check:production-env`.
- `scripts/deploy.sh` runs the same hosting-profile validator against `backend/.env` before deploy proceeds.
- `.github/workflows/ci.yml` runs `npm run check:production-env`.
- `backend/.env.shared.example` and `backend/.env.vps.example` now include `SESSION_COOKIE_SECURE=true`.

## Why This Matters

Security-sensitive configuration must fail closed in production. Logging missing secrets while continuing can create degraded production instances with disabled email, weak payment validation, missing JWT secret, broken CORS assumptions, or default credential fallback.

## Required Remediation

1. Convert required production env validation to fail-stop behavior.
2. Keep non-production warnings explicit and isolated.
3. Add startup tests for missing required production values.
4. Include env validation in release gates.

## Acceptance Gates

- `npm --prefix backend test -- --runTestsByPath tests/productionEnvValidation.test.js tests/productionEnvGuard.test.js tests/hostingProfilePreflight.test.js` - passed 3 suites / 17 tests on 2026-06-03.
- `npm run check:production-env` - passed on 2026-06-03.
- Production startup child-process regression proves missing required production env exits non-zero before server listen.
- Failure output reports variable names and validation reasons without secret values.
- Release gates now include the production env fixture check, and deploy validates the real `backend/.env` through the same validator.

## Residual Risk

- The validator can block deploys until real production `backend/.env` includes the required values. This is intended fail-closed behavior.
- Shared hosting remains a documented degraded profile; the validator enforces its explicit `fail_open`/local-temp/no-Redis contract instead of claiming VPS-grade guarantees.
