# Implementation Plan - 5.2 Job Order Completion lacks Transactional Atomicity

## User Feedback
> Make sure to create a plan that will be able to handle acting ups or database connection flickers when it comes to having the correct transactional atomicity. We need a 100% data integrity

## Finding Description
`completeJobOrder` loops through ingredients and calls `createStockMovement` for each without a wrapping transaction.

## Severity
🔴 Critical

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/jobOrderService.js`:
- `createJobOrder` is safe (wrapped in transaction).
- `completeJobOrder` (lines 321-554) is **unsafe**.
    - It iterates through ingredients and calls `createStockMovement` for consumption.
    - It calls `createStockMovement` for production output.
    - It updates `JobOrder` status.
    - **Issue**: These are separate, independent database commits.
- **Scenario**:
    - JO requires IngA and IngB.
    - IngA consumption succeeds (Stock deducted).
    - IngB consumption fails (e.g. database error, or temporary connection blip).
    - Function throws.
    - **Result**: IngA is gone, but JO is not marked complete. Retry might consume IngA *again* if not careful, or require manual fix.

### 2. Proposed Changes
Wrap `completeJobOrder` logic in a single transaction.

#### A. Modify `jobOrderService.js`
```javascript
export const completeJobOrder = async (...) => {
    const sequelize = dbStore.getStore()?.sequelize || dbStore.get('sequelize');
    
    // Start Transaction
    return await sequelize.transaction(async (t) => {
        // ... Retrieve JO ...
        
        // Loop Ingredients
        for (const ingredient of jo.ingredients) {
            // ... Validation ...
            
            // Pass transaction 't' to sub-service
            await createStockMovement({ ... }, userId, t);
            
            // Pass transaction 't' to update
            await ingredient.update({ ... }, { transaction: t });
        }
        
        // Production Output
        await createStockMovement({ ... }, userId, t);
        
        // Update JO Status
        await jo.update({ ... }, { transaction: t });
        
        return result;
    });
};
```
