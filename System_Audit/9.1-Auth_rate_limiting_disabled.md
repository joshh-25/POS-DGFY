# Implementation Plan - 9.1 Authentication Rate Limiting Disabled

## User Feedback
> Enable it, but always remember that if needed for testing, we can disable it at any time and nothing is affected in the production server

## Finding Description
The `authLimiter` middleware is defined as a pass-through function, leaving login endpoints vulnerable to brute-force.

## Severity
🟠 High

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/middleware/rateLimiter.js`:
- `authLimiter` is explicitly disabled (Lines 49-70).
- **Code**: `export const authLimiter = (req, res, next) => next();`
- The actual implementation using `rateLimit` is commented out.
- **Vulnerability**: Brute-force attacks on `/api/v1/auth/login` and `register` are not throttled at the application level.
- **Severity**: High (allows password guessing).

### 2. Proposed Changes
Re-enable `authLimiter` with strict limits.

#### A. Modify `rateLimiter.js`
1.  Uncomment the `authLimiter` implementation.
2.  Set defaults: 15 minutes window, 5 attempts (Production).
3.  Ensure `trustProxy` logic in `server.js` aligns with `validate: { trustProxy: false }` here, or remove the validation override if `server.js` handles it.

```javascript
/* rateLimiter.js */
export const authLimiter = rateLimit({
  windowMs: authWindowMs, // 15 mins
  max: authMaxRequests,   // 5 attempts
  message: createRateLimitError('Too many authentication attempts, please try again later.'),
  standardHeaders: true,
  legacyHeaders: false,
  handler: (req, res) => {
    logger.warn('Auth rate limit exceeded', {
      ip: req.ip,
      path: req.path
    });
    res.status(429).json(createRateLimitError('Too many authentication attempts.'));
  }
});
```

### 3. Verification Plan

#### Automated Test
1.  Set `RATE_LIMIT_AUTH_MAX_REQUESTS=2` in .env (or mock logic).
2.  Send 3 POST requests to `/api/v1/auth/login` with invalid credentials.
3.  **Expect**:
    - Request 1: 401
    - Request 2: 401
    - Request 3: 429 Too Many Requests

### 4. Risk Assessment
- **Impact**: High (Security improvement).
- **Risk**: Legitimate users behind NAT/Shared IP might get blocked if `trust proxy` is misconfigured.
    - *Mitigation*: Ensure `server.js` correctly sets `app.set('trust proxy')`.

### 5. Files to Change
- `backend/src/middleware/rateLimiter.js`
