# Implementation Plan - 7.3 Potential Operator Injection via Query Parameters

## User Feedback
> Develop a development plan that ensures bad sql injections are not permitted

## Finding Description
Usage of `req.query` directly in Sequelize operators allows operator injection (e.g., `?startDate[gt]=...`).

## Severity
🟡 Medium

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/controllers/analyticsController.js`:
- The `getAnomalies` function (Lines 37-43) destructures `req.query` and passes values to `analyticsService`.
- **Code**:
    ```javascript
    const { category, itemId, days } = req.query;
    const options = {
        category: category || null, // Vulnerable to Object Injection
        itemId: itemId ? parseInt(itemId) : null, // Safe (parseInt)
        days: days ? parseInt(days) : 30 // Safe (parseInt)
    };
    ```
- **Vulnerability**: Express/Qs parses `?category[$ne]=null` as `category: { $ne: null }`.
- In `analyticsService.js`, this object is assigned to `where.category`.
- **Result**: Sequelize interprets `$ne` (or `[Op.ne]`) and changes the query logic. If a user injects `category[$ne]=null`, it returns *all* categories, bypassing a intended filter (if one was meant to be strict). Or they could inject other operators to leak data.

### 2. Proposed Changes
Sanitize inputs to ensure they are primitives (Strings).

#### A. Modify `getAnomalies` in `analyticsController.js`
Explicitly cast `category` to String or validate type.

```javascript
/* analyticsController.js */
const { category, itemId, days } = req.query;

const options = {
    // Fix: Ensure string if present
    category: category ? String(category) : null,
    itemId: itemId ? parseInt(itemId) : null,
    days: days ? parseInt(days) : 30
};
```

#### B. Audit other controllers
- `reportController.js`: `type` parameter (Line 95) is used in a `switch`. Safe.
- `req.query` usage in `getSupplierPerformance`, `getItemBurnRate` seems parsed or used as ID.
- **Rule**: Always clean `req.query` parameters before passing to Services/Sequelize.

### 3. Verification Plan

#### Automated Test
1.  Spy on `analyticsService.detectAnomalies`.
2.  Call API with `?category[$ne]=null`.
3.  **Expect**: Service receives `{ category: "[object Object]" }` (if String() applied) or the Controller rejects it.
    - *Goal*: The Service should NOT receive an Object `{ $ne: null }`.
    - If `String(obj)` is used, it becomes `"[object Object]"`, which is safe (just won't match any category).

### 4. Risk Assessment
- **Impact**: Low (Data Leak/Logic Bypass).
- **Regression**: None, assuming valid inputs are strings.
