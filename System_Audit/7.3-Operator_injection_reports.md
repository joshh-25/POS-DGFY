#  RESOLVED - 7.3 Potential Operator Injection via Query Parameters

## Status
Resolved

## Severity
Medium

## Root Cause
Usage of `req.query` directly in Sequelize operators allows operator injection (e.g., `?startDate[gt]=...`).

## Fix Implemented
### Root Cause
Express defaults to the `qs` query string parser, which parses bracket notation like
`?status[$ne]=active` into nested objects `{ status: { $ne: 'active' } }`. Sequelize interprets
these as operator expressions, enabling attackers to bypass filters or leak data.

### Phase 1 Fix (Partial  Conversation pre-7.3)
Added `typeof category === 'string'` guard to `analyticsController.getAnomalies` (line 41).
This protected only one parameter on one endpoint.

### Phase 2 Fix (Global  Conversation f8729b0f)
Set `app.set('query parser', 'simple')` in `server.js` to switch Express from `qs` to Node's
built-in `querystring` module. This ensures **all** `req.query` values across **all endpoints**
are always flat strings or arrays  never nested objects. One line, zero regression risk.

### Files Changed
| File | Change |
|---|---|
| `backend/src/server.js` | Added `app.set('query parser', 'simple')` after app creation |
| `backend/src/controllers/analyticsController.js` | Phase 1 `typeof` guard (retained as defense-in-depth) |

### Impact
- **10+ endpoints** previously vulnerable are now protected globally.
- No frontend changes required (all existing query strings are flat `key=value`).
- No regression risk for legitimate API consumers.

### Verification
- `GET /api/v1/items?status[$ne]=active`  `status` is parsed as `undefined` (key becomes literal `"status[$ne]"`)
- `GET /api/v1/items?status=active`  Works normally, returns items with `status=active`
