## Finding Description
The backend `registerUser` generates JWT tokens and returns them, but the frontend registration flow redirects to login instead of using them, wasting resources.

## Severity
 Low

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/authService.js` (lines 115-125 of `registerUser`) and `backend/src/controllers/authController.js`, the registration flow automatically generates and returns a JWT pair (Access + Refresh Token) immediately after creating the user record.
- **Problem**: This creates "orphaned" tokens if the user registers but never actually uses the app, or if we introduce mandatory email verification later (where they *shouldn't* have a token yet). It also clutters the `authService` with token generation logic that belongs strictly to the "Login" domain.

### 2. Proposed Changes
Decouple **Registration** from **Authentication**.

#### A. Modify `registerUser` in `authService.js`
- Remove the call to `generateToken` and `generateRefreshToken`.
- Return only the user profile (id, email, username).

```javascript
// BEFORE
const token = generateToken(user);
const refreshToken = generateRefreshToken(user);
return { user, token, refreshToken };

// AFTER
return { 
    user_id: user.user_id,
    username: user.username,
    email: user.email,
    role: user.role,
    // No tokens here
};
```

#### B. Update `authController.register`
- Return 201 Created with the user profile.
- **Frontend Impact**: The frontend current functionality ("Auto-login after register") will break. We have two choices:
    1.  **Strict**: Redirect user to Login page after successful registration.
    2.  **Convenience**: Controller manually calls `loginUser` logic internally after register.
    
    *Decision*: We will adopt the **Strict** approach (Choice 1) as it is cleaner and paves the way for Email Verification. The frontend will need to handle the "Success -> Redirect to Login" flow.

### 3. Verification Plan

#### Automated Test
1.  Call `POST /auth/register` with new user details.
2.  **Expect**: 201 Created. Body contains user info but `data.token` is undefined.

#### Manual Verification
1.  Register a new user via UI.
2.  **Expect**: UI shows "Registration Successful" and redirects to Login page (requires frontend update).
3.  **Expect**: No auto-login.

### 4. Risk Assessment
- **Impact**: Medium. Breaking change for Frontend.
- **Mitigation**: Update `frontend/src/services/authService.js` to stop expecting a token in the register response.
