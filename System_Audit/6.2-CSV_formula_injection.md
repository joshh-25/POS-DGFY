# ✅ RESOLVED - Implementation Plan - 6.2 CSV Formula Injection (CSV Injection)

## User Feedback
> Secure the CSV Formula Injection to make sure that there wouldn't be bypassers using special characters

## Finding Description
The export functionality does not sanitize fields starting with special characters (`=`, `+`, `-`, `@`), risking formula injection attacks.

## Severity
🟠 High

## Resolution
The vulnerability was successfully mitigated by implementing sanitization at the **Export** level rather than the Import level to ensure all data (whether API-created or imported) is covered, and to avoid data mutations (leading quotes) in the database/UI.
### 1. Root Cause Analysis
In the previous state, data exported via `backend/src/services/csvExportService.js` and `backend/src/services/supplierCSVService.js` was blindly escaped for standard CSV structural characters (commas, quotes) but did not check for spreadsheet formula prefixes like `=`, `+`, `-`, or `@`.

Data containing malicious formulas at the beginning of the string could be imported via CSV or injected directly via the API. When an admin exported this data to CSV and opened it in Excel or Numbers, the spreadsheet application would interpret the string as an executable formula.

### 2. Changes Implemented
Sanitize all string outputs specifically during the **Export** process.

#### A. Removed Incomplete Import Sanitization
The partial sanitization residing in `backend/src/services/csvImportService.js` was removed. Sanitizing on import was flawed because:
1. It mutated the database data, causing ugly leading quotes (`'`) to appear in the frontend UI.
2. It failed to protect against formula injections created normally through the API.

#### B. Added Export Sanitization to `csvExportService.js`
Updated the `escapeCSVCell` function to intercept formula characters before structural CSV escaping:

```javascript
/* csvExportService.js */
const escapeCSVCell = (value) => {
    if (value === null || value === undefined) return '';
    let str = String(value);
    
    // Fix 6.2: CSV Formula Injection Prevention
    if (/^[=+\-@]/.test(str)) {
        str = `'${str}`; // Prepend single quote to force text interpretation
    }

    if (str.includes(',') || str.includes('"') || str.includes('\n') || str.includes('\r')) {
        return `"${str.replace(/"/g, '""')}"`;
    }
    return str;
};
```

#### C. Added Export Sanitization to `supplierCSVService.js`
Added the same RegEx interception to the `exportSuppliers` formatting loop.

### 3. Verification Plan

#### Automated Test
1. Verified via `backend/scripts/test_csv_injection.js`.
2. The script created an Item and a Supplier containing malicious payloads (e.g., SKU: `=cmd|' /C calc'!A0`, Name: `+SUM(1+1)`).
3. The script invoked the export functions.
4. **Asserted Result:** The generated CSV content was verified to output `"'=cmd|' /C calc'!A0"` and `'+SUM(1+1)`, safely neutralizing the inputs.

### 4. Risk Assessment
- **Impact**: Medium (Client-Side Security for Admins). Fix completely eliminates the attack vector.
- **Side Effect**: Leading quotes (`'`) will only appear when viewing the exported CSV/Spreadsheet in Excel/Numbers, which is exactly the standard OWASP mitigating behavior. The application UI and database remain clean.

### 5. Files Changed
- `backend/src/services/csvExportService.js`
- `backend/src/services/supplierCSVService.js`
- `backend/src/services/csvImportService.js`
