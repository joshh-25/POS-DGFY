# [OPEN] 5.2 AI Red-Team and Cost-Abuse Gate Missing Current Evidence

Severity: Medium
Audit area: AI safety, prompt injection, abuse control

## Re-Baseline Update (2026-08-05)

**Still open; only marginal, non-AI-specific progress.** No adversarial test coverage exists anywhere in the tree — searching for prompt-injection terms across `backend/tests`, `backend/src`, and `docs` returns only the AI transport handler itself and an archived March-2026 audit finding, zero test files. `backend/tests/ai_cost_control_e2e.test.js` covers only usage/cost *logging*, not ceiling *enforcement*. The one real control that shipped is scoped narrowly: `backend/src/modules/menuImport/usecases/createMenuImportJobUseCase.js:89-95` enforces a per-tenant daily AI spend budget (`MENU_IMPORT_BUDGET_EXCEEDED`), but it covers only the `menu_import` and `item_image_generation` features — `backend/src/config/aiUsageFeatures.js` shows the primary `ai_assistant` feature has no budget at all. `backend/src/routes/ai.js` has no route-level rate limiter beyond the blanket general API limiter. All four acceptance gates still fail.

## Finding

The current AI validation proves registry shape, but the audit did not find current release-gate evidence for adversarial prompt-injection, tool-abuse, data-exfiltration, or cost-abuse tests.

## Evidence

- `npm run ai:check` validated tool definitions and handlers.
- The command did not provide adversarial prompt test evidence.
- No current release-gate artifact from this audit showed AI red-team coverage.

## Why This Matters

LLM-backed features introduce risks beyond schema validity. Tool injection, malicious file content, unauthorized data access, overbroad tool calls, and runaway cost loops need explicit tests and operational limits.

## Required Remediation

1. Add AI red-team tests covering prompt injection, tenant data isolation, unauthorized tool invocation, and hostile document/file content.
2. Add token, cost, and rate ceilings per tenant/user/workflow.
3. Log AI tool invocation decisions without exposing secrets.
4. Add a release gate or scheduled audit for AI safety tests.

## Acceptance Gates

- AI adversarial tests are runnable and green.
- AI usage has per-tenant cost and rate controls.
- Tool calls are permission-checked against tenant and user scope.
- Release evidence includes AI safety coverage.
