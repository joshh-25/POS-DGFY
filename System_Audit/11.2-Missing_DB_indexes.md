## Finding Description
The original concern was missing index coverage for high-frequency FK/query columns (`item_id`, `batch_id`, `product_id`, plus item filters such as `sku_code`, `category`, `folder_id`, `deleted_at`).

## Root Cause
- The issue was historically valid during earlier schema iterations.
- Index coverage was added over time across model definitions and migrations, but this audit note was left in an outdated "proposed" state.
- A residual legacy filter path still used `items.product_folder` in CSV export, which could full-scan `items`.

## Evidence Collected
1. Indexes already present in models:
   - `backend/src/models/Item.js` (`sku_code`, `category`, `folder_id`, `deleted_at`, `status`)
   - `backend/src/models/StockMovement.js` (`item_id`, `movement_type`, `timestamp`, composite `item_id,movement_type,timestamp`)
   - `backend/src/models/JobOrder.js` (`product_id`, `status`)
2. Index coverage already present in migrations:
   - `backend/migrations/20240101000014-create-stock-movements.js`
   - `backend/migrations/20240101000012-create-job-orders.js`
   - `backend/migrations/20260202000003-update-items-folder-relation.js`
   - `backend/migrations/20260106000001-add-fifo-shelf-life-columns.js`
   - `backend/migrations/20260301000000-add-performance-indexes.cjs`
3. Live DB verification (active tenant DBs):
   - All required targeted columns had index coverage.
   - FK coverage audit returned zero missing leftmost FK indexes.
4. Residual performance gap validation:
   - `EXPLAIN ... WHERE product_folder='...'` showed full scan (`type=ALL`, `key=NULL`) before hardening.

## Final Implementation
1. **CSV export folder filtering moved to indexed path**
   - `backend/src/services/csvExportService.js` now resolves folder name via `item_folders.name` and filters by `items.folder_id`.
   - API input remains `folder` for backward compatibility.
   - `product_folder` is preserved in export output for legacy compatibility metadata.
2. **Formal index contract added**
   - `backend/src/config/requiredIndexContract.js` defines required single/composite indexes.
3. **Automated schema index audit service added**
   - `backend/src/services/schemaIndexAuditService.js`
   - Discovers active tenant DBs from `tenants` table (fallback: current DB).
   - Audits `information_schema.STATISTICS`.
   - Returns structured healthy/degraded status with missing index list.
4. **Runtime health degradation guard added**
   - `backend/src/server.js`
   - Runs audit on startup + every 6 hours (non-blocking).
   - `/health` now includes `services.schemaIndexes`.
   - Health returns `503` when required indexes are missing (without stopping server startup).
5. **CI enforcement added**
   - `backend/scripts/audit-indexes.js`
   - `npm run audit:indexes`
   - `.github/workflows/ci.yml` now runs index audit after tests/migrations.
6. **Documentation updated**
   - `docs/database/schema.md` now documents canonical folder filtering (`folder_id`) and runtime/CI index guard behavior.

## Security and Performance Outcome
- Original 11.2 indexing concern is resolved for current schema and active tenants.
- Index drift is now continuously guarded by runtime health monitoring and CI failure enforcement.
- Legacy `product_folder` full-scan path was removed from CSV export filtering.
