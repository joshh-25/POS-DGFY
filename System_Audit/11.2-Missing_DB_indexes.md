# Implementation Plan - 11.2 Missing Database Indexes on Foreign Keys

## User Feedback
(Pending User Feedback)

## Finding Description
Critical foreign keys used for frequent lookups (`item_id`, `batch_id`, `product_id`) do not have database indexes defined in the model.

## Severity
🟠 High

## Proposed Plan

### 1. Root Cause Analysis
- **Current State**: `Item.js` (and likely others) relies on Sequelize default indexing (Primary Keys only).
- **Missing**:
    - `sku_code`: Used for lookups. `unique: false` (should be true per tenant? or globally?).
    - `folder_id` and `category`: Used for filtering.
    - `deleted_at`: Used for soft delete filtering (if enabled).
- **Performance**:
    - Queries like `WHERE product_folder = 'Cakes'` scan the entire `items` table.
    - As inventory grows (e.g. 10k items), Dashboard load times will degrade linearly.

### 2. Proposed Changes
Add explicit indexes to Models.

#### A. Modify `Item.js` (and others)
Add `indexes` array to options.

```javascript
/* Item.js */
}, {
  tableName: 'items',
  // ...
  indexes: [
    { fields: ['sku_code'] }, // Add unique if needed
    { fields: ['folder_id'] },
    { fields: ['category'] },
    { fields: ['deleted_at'] } // Speed up non-deleted checks
  ]
});
```
*Note: Sequelize Sync might not apply these automatically to existing tables without `alter: true`. Better to create a migration.*

### 3. Verification Plan
1.  Run `EXPLAIN SELECT * FROM items WHERE category = 'product';`.
2.  **Expect**: `type: ALL` (Full Scan) -> `type: ref` (Index Scan).

### 4. Risk Assessment
- **Impact**: High (Performance).
- **Complexity**: Medium (Migration needed).

### 5. Files to Change
- `backend/src/models/Item.js`
- `backend/src/models/StockMovement.js` (itemId index)
