# Implementation Plan - 4.4 Missing per-tenant AI cost controls

## User Feedback
> Just track token usage but we do not need to limit their token usage per tenant or user

## Finding Description
No mechanisms exist to track or limit token usage per tenant or user.

## Severity
🟢 Low

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/services/aiService.js`:
- The code calls `openai.chat.completions.create`.
- It extracts `response.choices[0].message`.
- **Missing**: It ignores `response.usage` (which contains `prompt_tokens`, `completion_tokens`).
- **Result**: No record of how much each tenant is spending. No way to bill them or enforce limits.

### 2. Proposed Changes
Implement "AI Metering and Quotas".

#### A. Database Schema
Create `AiUsageLog` model:
- `id` (UUID)
- `tenant_id` (UUID)
- `user_id` (UUID)
- `model` (String, e.g., 'gpt-4')
- `input_tokens` (Int)
- `output_tokens` (Int)
- `cost_usd` (Decimal, calculated based on model rates)
- `timestamp` (Date)

#### B. Modify `aiService.js`
1.  **Ingest**: After every successful API call, save to `AiUsageLog`.
2.  **Enforce**: Before calling API, check if Tenant's *Monthly Total* > *Plan Limit*.

```javascript
// Rate Card (could be in DB/Config)
const RATES = {
    'gpt-4o': { input: 5.00/1000000, output: 15.00/1000000 }
};

// In processMessage / handleToolCalls check logic
const { usage } = response;
if (usage) {
    const cost = calculateCost(MODEL, usage.prompt_tokens, usage.completion_tokens);
    await AiUsageLog.create({
        tenant_id: user.tenant_id,
        user_id: user.user_id,
        model: MODEL,
        input_tokens: usage.prompt_tokens,
        output_tokens: usage.completion_tokens,
        cost_usd: cost
    });
}
```

### 3. Verification Plan

#### Automated Test
1.  Mock OpenAI response to include `{ usage: { prompt_tokens: 10, completion_tokens: 5 } }`.
2.  Call `processMessage`.
3.  **Expect**: New row in `AiUsageLog`.

#### Manual Verification
1.  Send a message in the Chat UI.
2.  Check the database `ai_usage_logs` table.
3.  Verify token counts match (roughly) the message length.

### 4. Risk Assessment
- **Impact**: Medium (Financial protection).
- **Mitigation**: Ensure logging is async (don't block response) but reliable.
