## Finding Description
`upgradeToPremium` in `paymentController.js` called `paypalService.verifySubscription()` and then checked:
```javascript
if (!subDetails || (subDetails.status !== 'ACTIVE' && subDetails.status !== 'APPROVAL_PENDING'))
```
`APPROVAL_PENDING` is PayPal's state for "user started checkout but payment has not cleared." The condition above passed `APPROVAL_PENDING` through as valid, granting premium access without confirmed payment.

**Secondary Vulnerability (Found by Gemini Flash)**:
`registerCompanyRequest` in `adminTenantController.js` also accepted `APPROVAL_PENDING` for auto-approval of new company tenants.
```javascript
if (subDetails && (subDetails.status === 'ACTIVE' || subDetails.status === 'APPROVAL_PENDING')) {
    initialStatus = 'active'; // Auto-approve
```

## Severity
🔴 Critical

## Proposed Plan

### 1. Root Cause Analysis
In `backend/src/controllers/paymentController.js` — `upgradeToPremium`:
```javascript
// VULNERABLE — before fix
const subDetails = await paypalService.verifySubscription(subscriptionId);
if (!subDetails || (subDetails.status !== 'ACTIVE' && subDetails.status !== 'APPROVAL_PENDING')) {
    return res.status(400).json({ ... });
}
// Reaching here grants plan: 'premium'
```
- **Attack**: Authenticated user starts PayPal subscription flow → copies subscription ID from redirect URL → calls `POST /api/v1/payments/upgrade` before paying → gets premium plan.
- **Why it matters**: The `/upgrade` route is protected by `authenticate` middleware, but ALL logged-in users have a valid JWT. The only real guard was this status check.

### 2. Fix Applied by Claude Code
```javascript
// FIXED — only ACTIVE passes
const subDetails = await paypalService.verifySubscription(subscriptionId);
if (!subDetails || subDetails.status !== 'ACTIVE') {
    return res.status(400).json({
        success: false,
        message: 'Subscription is not active. Current status: ' + (subDetails?.status || 'Unknown')
    });
}
```

### 3. Fix Applied by Gemini Flash (adminTenantController.js)
```javascript
// FIXED — only ACTIVE allows auto-approval
if (subDetails && subDetails.status === 'ACTIVE') {
    initialStatus = 'active'; // Auto-approve
    subscriptionStatus = 'active';
    validatedSubscriptionId = subscriptionId;
} else {
    // Falls through to manual review or rejection
    throw new Error('Subscription verification failed. Status: ' + (subDetails?.status || 'Unknown'));
}
```
