# Audit 3.6 - Upgrade endpoint accepts unpaid subscriptions

## Status
Resolved

## Severity
Unspecified

## Root Cause
The entitlement gate in `POST /api/v1/payments/upgrade` previously allowed `APPROVAL_PENDING` subscriptions, which could grant premium access before payment completion.

A parity issue existed in premium company registration: auto-approval also accepted `APPROVAL_PENDING`.

## Fix Implemented
1. Upgrade gate is now strict ACTIVE-only.
- `upgradeToPremium` rejects all non-`ACTIVE` statuses.
- Evidence: `backend/src/controllers/paymentController.js` (`upgradeToPremium`, around lines 434-453).

2. Premium registration auto-approval is now strict ACTIVE-only.
- `registerCompanyRequest` only auto-approves premium tenants when PayPal returns `ACTIVE`.
- Evidence: `backend/src/controllers/adminTenantController.js` (around lines 98-117).

3. Engagement telemetry is idempotent and correlation-safe.
- Upgrade/registration attempt and outcome events are written with `useIdempotency: true`.
- Correlation id uses `x-request-id` with UUID fallback, so retries can be deduped.
- Evidence:
  - `backend/src/controllers/paymentController.js` (around lines 404-417, 438-449, 502-514)
  - `backend/src/controllers/adminTenantController.js` (around lines 34-52, 83-91, 120-130, 165-178)
  - `backend/src/services/engagementService.js` (idempotency key + `findOrCreate`, around lines 53-67)

## Test Evidence
1. Route + DB integration proof
- `backend/tests/subscriptionIntegration.test.js`
- Verifies unpaid upgrade is blocked at HTTP boundary, tenant state remains non-premium, and exact event-pair contracts are persisted.
- Verifies retry with same `x-request-id` does not duplicate events.

2. Status-gate contract tests
- `backend/tests/paypalUpgradeValidation.test.js`
- `backend/tests/adminTenantRegistrationValidation.test.js`
- These validate PayPal status interpretation logic but are not full-route DB integration tests.
