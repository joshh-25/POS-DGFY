<objective>
Prove — before any frontend work — that the old->new DGFY data migration (accounts + tenants, legacy sku_* -> dgfy_core/dgfy_business_*) works repeatably at real production tenant volume, running the migration exactly as production will: a one-shot containerized migration-runner, beside the live base platform (GHCR :develop images), nothing repointed. Capture the proof as a committed runbook + evidence pack.

Purpose: Deliver Phase 7 / CMP-05 Success Criterion 1 (rehearsal runtime, realistic data-volume evidence, operator-visible migration reports) as a pre-cutover, pre-frontend gate — so a genuinely broken migration is caught and fixed via clone-and-retry, never discovered during the real cutover window.
Output: A proven, repeated-clean rehearsal loop plus a new committed runbook, docs/database/dgfy-migration-rehearsal-production-volume.md, documenting the methodology and citing the captured evidence.
</objective>
