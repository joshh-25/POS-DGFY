<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dgfy_* database → backup artifact (dump file on disk) | Real tenant/account PII crosses from a live database into a flat file in the working tree; refactor-do-not-commit/ is untracked but NOT git-ignored, so a mis-placed dump could be staged and committed. |
| source dgfy_* → restored *_restore database | Integrity boundary: a restore that "succeeds" (mysql exit 0) but does not faithfully reproduce the data would give false recoverability confidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-02-01 | Information Disclosure | dgfy_* backup dump file (tenant/account PII) | high | mitigate | Backup script writes dumps only under the clone's ./data/ prefix, which the harness .gitignore ignores (verified: data/ ignored, reports/ not); runbook states dumps are PII and must never be staged/committed/shared and live only in the disposable clone workspace. |
| T-07-02-02 | Tampering | restore verification (integrity oracle) | high | mitigate | Restore proof does not trust mysql exit status: it compares per-table row counts source-vs-restore (fail-nonzero on mismatch) AND re-runs the runner's own verify against the restored databases requiring summary.data_migration_ok:true — a vacuous/partial restore cannot pass. |
| T-07-02-03 | Elevation of Privilege | root TARGET_DB credentials used for dump/CREATE DATABASE | low | accept | Root creds are the disposable-clone-only localtest_root_pw already in the harness compose (never production creds); the proof runs only against a throwaway clone, dropped after the attempt. |
| T-07-02-04 | Denial of Service (data loss) | source dgfy_* databases during proof | medium | mitigate | Script is read-only against source databases (dump only; restore targets are new *_restore databases); acceptance test greps to confirm no source DROP/ALTER and no sku_* touch. |

No npm/pip/cargo package installs are introduced by this plan (mysqldump ships in the mysql:8.0 image already in the harness stack), so no supply-chain (T-07-02-SC) legitimacy checkpoint is required.
</threat_model>
