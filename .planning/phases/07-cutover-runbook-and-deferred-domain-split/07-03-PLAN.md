<objective>
Deliver Phase 7 / CMP-05 Success Criterion 3: explicitly capture that Product, POS checkout, payment, fiscal, and frontend migration scope is deferred into post-foundation planning instead of entering v1 implementation. This plan writes a single committed register doc that makes that deferral explicit and traceable by cross-referencing the already-tracked homes of the deferred scope — REQUIREMENTS.md's v2 section and PROJECT.md's Out of Scope section — rather than duplicating them.

Purpose: The deferred scope is already recorded in several places (REQUIREMENTS.md v2, PROJECT.md Out of Scope, STATE.md Deferred Items), but it is not consolidated into one discoverable, auditable statement tied to Phase 7 SC3. This register closes that gap so a future reader (or a post-foundation planning cycle) can see, in one place, exactly which domains were held out of v1 and where each is tracked. This is the SC3 documentation deliverable — not the implementation of any deferred domain.
Output: A committed doc, docs/database/dgfy-deferred-domain-split.md, that lists each deferred domain, links it to its v2 requirement ID and Out-of-Scope rationale, and states plainly it enters post-foundation planning, not v1.
</objective>
