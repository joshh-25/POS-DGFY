<threat_model>
OWASP ASVS Level 1 framing: verification is the release evidence boundary; it must fail closed on unknown metadata, unresolved conflicts, unsafe target lists, and audit gaps.

| Threat | STRIDE | Severity | Component | Disposition | Mitigation / Block Condition |
|--------|--------|----------|-----------|-------------|------------------------------|
| Target-list tampering | Tampering | high | `verifyData.js` | mitigate | Verification uses the same manifest validator and reports target coverage; block if verify can run data checks without manifest. |
| SQL injection / unsafe DB names | Tampering | high | `verifyData.js` | mitigate | Use validated manifest/env DB names and parameterized values. |
| Secret leakage in reports | Information Disclosure | high | verify reports/runbook | mitigate | Report counts, IDs, reason codes, and relationships only; block if fixtures leak passwords, terminal secrets, OTPs, or `company_token`. |
| Privilege escalation through inferred memberships | Elevation of Privilege | high | relationship checks | mitigate | Verification fails when assignments/memberships exist without accepted membership evidence. |
| Duplicate writes on retry | Tampering | high | integration rehearsal | mitigate | Gated integration test reruns apply and checks no duplicate target rows. |
| Repudiation / audit gaps | Repudiation | high | verify command | mitigate | Verify fails/flags missing command execution, map, checkpoint, or finding evidence; idempotency cannot be clean when metadata is unknown. |
</threat_model>
