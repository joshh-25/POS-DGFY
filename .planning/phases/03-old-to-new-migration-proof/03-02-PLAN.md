<threat_model>
OWASP ASVS Level 1 framing: mappings are an access-control and data-minimization boundary because they decide what identity, membership, and terminal facts become canonical DGFY data.

| Threat | STRIDE | Severity | Component | Disposition | Mitigation / Block Condition |
|--------|--------|----------|-----------|-------------|------------------------------|
| Target-list tampering | Tampering | medium | mapping fixtures | mitigate | Mappers consume manifest-scoped targets from 03-01 only; no mapper can enumerate all tenants. |
| SQL injection / unsafe DB names | Tampering | low | `mappings.js` | mitigate | Pure mappers generate payloads only; no SQL construction is allowed in this plan. |
| Secret leakage in reports | Information Disclosure | high | terminal/account mappers | mitigate | Tests must prove password hashes, terminal password hashes, pairing secrets, OTPs, and `company_token` are absent from report-facing finding payloads except target `accounts.password_hash` when intentionally preserved for account migration. |
| Privilege escalation through inferred memberships | Elevation of Privilege | high | membership/assignment mappers | mitigate | Block if tests show assignment/business membership creation without accepted membership evidence per ADR 0028. |
| Duplicate writes on retry | Tampering | medium | ID-map key generation | mitigate | Every insert/update mapper emits a deterministic `legacy_id_map` key used by 03-04. |
| Repudiation / audit gaps | Repudiation | medium | finding classifications | mitigate | Every skip/conflict/orphan path emits structured reason code and remediation text. |
</threat_model>
