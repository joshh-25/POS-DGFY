## Trust Boundaries

|----------|-------------|
| client -> businesses routes | Authenticated user input crosses into create-business and registry lookup use cases. |
| landlord db -> registry metadata response | Tenant database pointers are transformed into a public-safe response. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06-01 | Spoofing | `GET /businesses/:id/tenant-registry` | high | mitigate | Require authenticated account and active landlord membership before returning metadata. |
| T-04-06-02 | Information Disclosure | `BusinessDatabaseRegistryRepository.toSafeMetadata` | high | mitigate | Return only safe fields and test that credentials/connector config are absent. |
| T-04-06-03 | Tampering | tenant database name generation | high | mitigate | Generate names server-side from opaque suffix; never accept public caller database names. |
| T-04-06-04 | Elevation of Privilege | registry lookup use case | high | mitigate | Deny non-members and keep activation/session creation in the existing separate use case. |
