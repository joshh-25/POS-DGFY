- `findById(businessId, id)` — returns location from business's tenant DB

- `findPrimary(businessId)` — returns the primary location

- `restore(businessId, id)` — un-soft-delete (set is_active=true)

**Key Implementation:**
- All queries are tenant-database-aware (use TenantConnector to access correct DB)
- create() checks if this is first location; if yes, auto-sets is_primary=true
- updatePrimary() ensures only one location per business has is_primary=true
- Transactions used for multi-step operations

**Error Handling:**
- Return null on not-found; let use cases validate
- Wrap DB errors in structured format

<task type="auto">
  <name>Task 3: Create Location Use Cases — locationUseCases.js</name>
  <files>apps/dgfy-api/src/modules/businesses/usecases/locationUseCases.js</files>
  <action>
Create locationUseCases.js with builders:

**buildCreateLocationUseCase({repository})**
- Input: {businessId, name, address_line, latitude?, longitude?, setAsPrimary?}
- Validates name required; address_line optional
- Calls repository.create() (auto-sets is_primary if first)
- If setAsPrimary=true and not first: calls repository.updatePrimary()
- Returns ApplicationResult.success({location})
- Returns ApplicationResult.failure if validation fails

**buildListLocationsUseCase({repository})**
- Input: {businessId, includeInactive?}
- Calls repository.findAll(businessId)
- Filters out inactive by default; includes if includeInactive=true
- Returns ApplicationResult.success({locations: [...]})

**buildGetLocationUseCase({repository})**
- Input: {businessId, locationId}
- Calls repository.findById(businessId, locationId)
- Returns ApplicationResult.success({location})
- Returns NOT_FOUND if location doesn't exist or belongs to different business

**buildUpdateLocationUseCase({repository})**
- Input: {businessId, locationId, updates: {name?, address_line?, latitude?, longitude?, is_active?}}
- Validates fields
- Calls repository.update()
- Returns ApplicationResult.success({location})

**buildSetPrimaryLocationUseCase({repository})**
- Input: {businessId, locationId}
- Validates location exists
- Calls repository.updatePrimary(businessId, locationId)
- Returns ApplicationResult.success({location})
- Returns error if location doesn't exist

**buildDeleteLocationUseCase({repository})**
- Input: {businessId, locationId}
- Soft-delete: calls repository.delete() (sets is_active=false)
- Returns ApplicationResult.success({location: {id, ...}})
- Cannot delete last location; returns error if only location remains

All use cases return ApplicationResult; use DomainError for domain failures.

**businessRoutes.js update:**
Add location endpoints (nested under business resource):
```
POST /businesses/:businessId/locations — create location (HTTP 201)
GET /businesses/:businessId/locations — list locations (HTTP 200)
GET /businesses/:businessId/locations/:locationId — get location (HTTP 200)
PATCH /businesses/:businessId/locations/:locationId — update location (HTTP 200)
POST /businesses/:businessId/locations/:locationId/set-primary — set as primary (HTTP 200)
DELETE /businesses/:businessId/locations/:locationId — delete location (HTTP 200)
```

**Access Control:**
- All endpoints require authentication
- All endpoints require membership (user is member of business)
- POST/PATCH/DELETE require owner role

**Response Format:**
Use sendUseCaseResult for all responses.

**Error Mapping:**
- 201: Location created
- 200: Success
- 400: Validation error
- 403: Access denied (non-member or non-owner)
- 404: Location not found or business not found
- 409: Conflict (e.g., cannot delete last location)
