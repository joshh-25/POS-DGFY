**buildCreateTenantSessionUseCase({businessRepository, businessDatabaseRegistry})**
- Input: {businessId, accountId}
- Step 1: Validate landlord membership exists (repository.getMembership(accountId, businessId))
  - If no membership: return ApplicationResult.failure({code: 'NO_MEMBERSHIP'})
- Step 2: Resolve tenant database (businessDatabaseRegistry.findByBusinessId(businessId))
  - Gets database_name and stable_opaque_suffix
  - If not found: return ApplicationResult.failure({code: 'NO_TENANT_DATABASE'})
- Step 3: Validate tenant-local assignment (query tenant DB's AccountStaffAssignment where dgfy_account_id = accountId)
  - If no assignment: return ApplicationResult.failure({code: 'NO_TENANT_ASSIGNMENT'})
  - Exception: business owner (membership.role === 'owner') can skip assignment requirement
- Step 4: Build session context
  - Return ApplicationResult.success({
      business_id: businessId,
      tenant_database: database_name,
      dgfy_account_id: accountId,
      active_assignment: assignment (if staff),
      timestamp: now()
    })

**Enforcement of D-04 (API-04):**
- Membership validation is explicit (step 1)
- Tenant-local assignment or authorized scope (owner) is explicit (step 3)
- Both must succeed before tenant context is bound

**buildActivateBusinessSessionUseCase({businessRepository, businessDatabaseRegistry})**
- Input: {businessId, accountId}
- Uses same validation as CreateTenantSession but for mid-session switch
- Returns ApplicationResult.success({...}) or failure
- No re-login required; uses same session token

Both use cases return ApplicationResult; error codes drive HTTP status codes in controller.

Add tenant session endpoint to businessRoutes and create dedicated controller:

**tenantSessionController.js:**
```javascript
export function buildTenantSessionController(useCases) {
  return {
    async activateSession(req, res) {
      const { id: businessId } = req.params;
      const accountId = req.user.id;
      const result = await useCases.activateBusinessSession({ businessId, accountId });
      
      // Map error codes to HTTP status
      if (!result.success) {
        if (result.error.code === 'NO_MEMBERSHIP') return res.status(403).json(result.toJSON());
        if (result.error.code === 'NO_TENANT_ASSIGNMENT') return res.status(403).json(result.toJSON());
        if (result.error.code === 'NO_TENANT_DATABASE') return res.status(404).json(result.toJSON());
        return res.status(500).json(result.toJSON());
      }
      return res.status(200).json(result.toJSON());
    }
  };
}
```

**businessRoutes.js update:**
Add endpoint:
```javascript
router.post('/:id/activate-session', authenticate, (req, res, next) =>
  tenantSessionController.activateSession(req, res).catch(next)
);
```

**Error Handling per D-04:**
- 403 Forbidden: NO_MEMBERSHIP or NO_TENANT_ASSIGNMENT (explicit rejection)
- 404 Not Found: NO_TENANT_DATABASE (edge case; shouldn't happen in normal flow)
- 500 Server Error: generic error (unexpected)

These status codes make the authorization failure clear to client.
