## Known Stubs

**LocationRepository is an in-memory, businessId-scoped `Map`, not a real per-tenant MySQL database.**

- **File:** `apps/dgfy-api/src/modules/businesses/repositories/locationRepository.js`
- **Reason:** No `TenantConnector` exists in `apps/dgfy-api` yet to resolve a per-tenant database connection; no `BusinessDatabaseRegistry` model exists yet to map a `business_id` to its tenant `database_name`; no business tenant-database *provisioning* flow exists anywhere in this codebase (`apps/dgfy-migration-runner` only migrates schema into already-known `DGFY_BUSINESS_DB_NAMES` targets). All three are explicitly Wave 4 scope (`04-04-PLAN.md`'s key_links: "TenantConnector -> resolves per-tenant database"). Auto-creating/syncing a tenant database's schema from live request-handling code would also violate this project's explicit constraint (`.planning/PROJECT.md` Constraints: migrations must run from a dedicated one-shot container, not long-running API containers).
- **Isolation guarantee held anyway:** every `Map` is keyed by `businessId`, so cross-business data access is structurally impossible at the application layer even though physical storage isn't yet a separate per-tenant database — this satisfied the plan's tenant-isolation verification requirement.
- **Forward-compatibility hook:** `LocationRepository`'s constructor already accepts an optional `locationModel` dependency (the real Sequelize model from `../../../models/Tenant/Location.js`) so Wave 4 can swap the repository's internals for real tenant-connection-backed queries without changing any call sites (`locationUseCases.js`).
- **Precedent:** Identical pattern to the staff-onboarding `BusinessRepository` in-memory storage, explicitly sanctioned by the 04-03-PLAN.md and approved by the user at that plan's checkpoint.
- **Approval:** Explicitly reviewed and approved by the user at this plan's Task 8 `checkpoint:human-verify` gate.
- **Resolution:** To be resolved when Wave 4 (`04-04-PLAN.md`) delivers `TenantConnector` and `BusinessDatabaseRegistry`-backed real tenant persistence.
