## Objective

**Wave 2: Account & Business Routes & Controllers (Clean Architecture Transport)** exposes Wave 1 use cases through HTTP endpoints using dependency injection. Implements the Interface Adapter layer (controllers, routes) that translates HTTP ↔ Use Cases while keeping use cases decoupled from HTTP.

**Why this matters:** HTTP layer is the first touch point for clients (Interface Adapter per Clean Architecture). Wave 2 makes Wave 1 accessible via API while maintaining clean boundaries: controllers are transport-only; use cases are HTTP-unaware. Dependency Injection via index.js ensures testability and loose coupling (Dependency Inversion + Single Responsibility).

**Output:** Account HTTP endpoints (register, login, profile, lookup) with dependency-injected controllers + scaffolded business endpoints. All following Single Responsibility + Dependency Inversion principles.

**routes.js Structure (Per Clean Architecture - Routes define Express routing ONLY):**
```javascript
import express from 'express';

// routes.js receives use cases via dependency injection (from index.js)
export function createAccountRoutes(useCases) {
  const router = express.Router();

  // Routes are thin: define Express paths and call controller methods
  // Controllers receive useCases (passed to buildAccountController by index.js)
  
  router.post('/register', async (req, res, next) => {
    const { email, password, first_name, last_name, phone } = req.body;
    const result = await useCases.registerAccount({
      email, password, first_name, last_name, phone
    });
    res.status(result.isSuccess ? 201 : 400).json(result.toJSON());
  });

  router.post('/login', async (req, res, next) => {
    const { email, password } = req.body;
    const result = await useCases.loginAccount({ email, password });
    res.status(result.isSuccess ? 200 : 401).json(result.toJSON());
  });

  // ... more routes
  
  return router;
}
```

**accountController.js Structure (Per Clean Architecture - Controllers are HTTP-to-UseCase translators):**
```javascript
import { sendUseCaseResult } from '../../shared/controllers/useCaseResponder.js';

// Controller builder receives use cases via dependency injection
export function buildAccountController(useCases) {
  return {
    async register(req, res) {
      // Extract HTTP request data
      const { email, password, first_name, last_name, phone } = req.body;
      
      // Call use case (no business logic here; just orchestration)
      const result = await useCases.registerAccount({
        email, password, first_name, last_name, phone
      });
      
      // Format response via sendUseCaseResult (consistent formatting)
      return sendUseCaseResult(res, result, 201); // 201 for creation
    },

    async login(req, res) {
      const { email, password } = req.body;
      const result = await useCases.loginAccount({ email, password });
      return sendUseCaseResult(res, result, 200);
    },

    async getMe(req, res) {
      const accountId = req.user.id;
      const result = await useCases.getAccount({ accountId });
      return sendUseCaseResult(res, result, 200);
    },

    async updateProfile(req, res) {
      const accountId = req.user.id;
      const { email, password, first_name, last_name, phone } = req.body;
      const result = await useCases.updateAccountProfile({
        accountId,
        updates: { email, password, first_name, last_name, phone }
      });
      return sendUseCaseResult(res, result, 200);
    },

    async getAccount(req, res) {
      const { id: targetAccountId } = req.params;
      const requestingAccountId = req.user.id;
      const requestingRole = req.user.role;
      const result = await useCases.getAccountForAuthorization({
        accountId: targetAccountId,
        requestingAccountId,
        role: requestingRole
      });
      return sendUseCaseResult(res, result, 200);
    }
  };
}
```

**Key Requirements (Clean Architecture Boundaries):**
1. **Single Responsibility (S):** Controllers handle HTTP parsing only; use cases handle business logic
2. **Dependency Inversion (D):** Controllers receive useCases via function parameter (injected by index.js), never import directly
3. Controllers DO NOT import models directly (ESLint blocks this)
4. Controllers DO NOT import repositories directly (only via use cases)
5. All responses use sendUseCaseResult() — consistent formatting across all endpoints
6. Error handling via try/catch in routes or Promise rejection → next middleware
7. Request body validation happens in use cases, not controllers (controllers just extract and pass)
8. HTTP status codes mapped from ApplicationResult error codes:
   - ApplicationResult.success → HTTP 200 (or 201 for creation)
   - ApplicationResult.failure with code 'DUPLICATE_*' → HTTP 409 (conflict)
   - ApplicationResult.failure with code 'VALIDATION_ERROR' → HTTP 400 (bad request)
   - ApplicationResult.failure with code 'INVALID_CREDENTIALS' → HTTP 401 (unauthorized)
   - ApplicationResult.failure with code 'UNAUTHORIZED' → HTTP 403 (forbidden)
   - ApplicationResult.failure (generic) → HTTP 500 (server error)

**accounts/index.js (Dependency Injection Container — CRITICAL):**
```javascript
import bcrypt from 'bcryptjs';
import { Account as AccountModel } from '../../models/Landlord/Account.js';
import { AccountEntity } from './entities/accountEntity.js';
import { AccountRepository } from './repositories/accountRepository.js';
import {
  buildRegisterAccountUseCase,
  buildLoginAccountUseCase,
  buildUpdateAccountProfileUseCase,
  buildGetAccountUseCase,
  buildGetAccountForAuthorizationUseCase
} from './usecases/accountUseCases.js';
import { buildAccountController } from './controllers/accountController.js';
import { createAccountRoutes } from './routes.js';

// STEP 1: Create repository (receives Sequelize model)
const accountRepository = new AccountRepository(AccountModel);

// STEP 2: Build use cases (receive repository + entity + dependencies)
const registerAccountUseCase = buildRegisterAccountUseCase({
  repository: accountRepository,
  accountEntity: AccountEntity,
  hashPassword: (password) => bcrypt.hash(password, 10)
});

const loginAccountUseCase = buildLoginAccountUseCase({
  repository: accountRepository,
  bcrypt // for password comparison
});

const updateAccountProfileUseCase = buildUpdateAccountProfileUseCase({
  repository: accountRepository,
  accountEntity: AccountEntity,
  hashPassword: (password) => bcrypt.hash(password, 10)
});

const getAccountUseCase = buildGetAccountUseCase({
  repository: accountRepository
});

const getAccountForAuthorizationUseCase = buildGetAccountForAuthorizationUseCase({
  repository: accountRepository
});

// STEP 3: Freeze use cases (immutable; prevents accidental modification)
export const accountUseCases = Object.freeze({
  registerAccount: registerAccountUseCase,
  loginAccount: loginAccountUseCase,
  updateAccountProfile: updateAccountProfileUseCase,
  getAccount: getAccountUseCase,
  getAccountForAuthorization: getAccountForAuthorizationUseCase
});

// STEP 4: Export controller builder (receives use cases when called)
export const buildAccountControllerFactory = () => buildAccountController(accountUseCases);

// STEP 5: Export routes builder (receives controller factory or use cases)
export { createAccountRoutes };
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP Request → Controller | Untrusted input from client (JSON body, params, headers) |
| Controller → Use Case | Use cases receive parsed input; controller doesn't validate |
| Use Case → Repository | Use cases enforce business rules; repository trusts use cases |
| Session Token → Request | JWT/opaque token from client; middleware verifies authenticity |
