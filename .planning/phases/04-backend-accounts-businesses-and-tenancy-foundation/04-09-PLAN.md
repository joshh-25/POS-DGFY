## Rationale — Cross-Package Registry-Update Mechanism (LOCKED)

`updateStatus()` lives in `apps/dgfy-api`; the new command lives in `apps/dgfy-migration-runner`. The test helper reuses `updateStatus()` only because it runs INSIDE the dgfy-api test process where the `BusinessDatabaseRegistry` Sequelize model is already wired against dgfy-api's own connection.

**Chosen mechanism: a direct, contract-faithful `UPDATE` against `dgfy_core.business_database_registry` from the runner, using the runner's own target connection** (option (b) in the gap contract). Justification:

1. The runner enforces a hard package boundary — `apps/dgfy-migration-runner/src/config/db.js` explicitly documents it never imports the backend's `TenantConnector` and uses only its own `config/env.js` credentials. Reusing dgfy-api's `updateStatus()` would require constructing dgfy-api's model wiring/config inside the runner, breaking that boundary and adding a cross-package dependency.
2. `business_database_registry` lives in `dgfy_core`, which IS the runner's own `TARGET_DB` (`createTargetConnection`). The runner ALREADY reads this exact table via raw SQL in `verify.js`'s `checkTenantCoverage()` (`SELECT database_name FROM business_database_registry`) — a direct `UPDATE` on the same connection is established, boundary-respecting precedent.
3. The `UPDATE` writes exactly the columns `updateStatus()` writes — `status='active'`, `verified_at=<now>` — but keyed on the **unique** `database_name` (the CLI flag) rather than `business_id`. This is strictly safer: the test helper's own doc comment documents that `business_database_registry` has NO unique constraint on `business_id` (only on `database_name`), so keying the write on `database_name` structurally avoids the latent double-row misroute bug the helper had to work around.

`updateStatus()` remains the single source of truth for the transition semantics; this command reproduces those exact semantics (same columns, same `provisioning -> active/verified` transition) through the runner's own connection.
