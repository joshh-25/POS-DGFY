<objective>
Fix code review finding CR-01: `verify.js`'s `migration_metadata` section (lines 337-355) currently wraps the primary target's check AND the entire business-target loop in one shared try/catch, unlike `business_schemas` (lines 319-333) which correctly scopes try/catch per target. A mid-loop failure on any business target silently drops already-collected results for earlier targets, mislabels the error under the primary target's database name, and produces no entry at all for the target that actually failed. Since `idempotency` is derived directly from `migration_metadata`, this corruption cascades there too.

Purpose: Close the single unresolved gap from 02-VERIFICATION.md so Phase 02's `migration_metadata`/`idempotency` evidence (D-21/D-22, DBF-04/DBF-05) is trustworthy under partial multi-target failure, not just in the happy path.

Output: `verify.js`'s `migration_metadata` block scoped per target (primary target and each business target independently try/catch-wrapped, mirroring `business_schemas`'s existing pattern), plus a regression test in `phase02Verification.test.js` proving one business target's thrown error cannot drop or mislabel another target's finding.
</objective>
