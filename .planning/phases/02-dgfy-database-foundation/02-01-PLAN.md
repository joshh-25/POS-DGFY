<threat_model>
OWASP ASVS Level 1 framing: this runner is an internal operational tool, but schema migration commands cross high-impact database trust boundaries. Block high-risk issues in this plan before proceeding to schema migrations.

## Trust Boundaries
| Boundary | Description |
|---|---|
| CLI/operator input -> migration runner | Runtime mode, target DB, command, and destructive flag determine what can mutate schemas. |
| Runner -> `dgfy_migration_meta` | Metadata integrity proves what ran and whether it succeeded. |
| Runner -> target database | Incorrect target or destructive classification can alter protected schemas. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01-01 | Tampering | `schema.js` destructive gate | high | mitigate/block | D-17 pending-only destructive detection with tests for historical destructive migrations and pending destructive migrations. |
| T-02-01-02 | Repudiation | `command_executions` failure status | high | mitigate/block | D-18 failure paths call `recordCommandComplete(... failed ...)` after command start. |
| T-02-01-03 | Information Disclosure | summary/report paths | medium | mitigate | D-20 `/reports` default avoids lost reports; do not include DB credentials in reports. |
| T-02-01-04 | Spoofing | target DB naming | high | mitigate/block | Existing target guard remains required before schema migration; tests must keep non-`dgfy_` target rejection. |
| T-02-01-05 | Tampering | legacy `sku_*` schemas | high | mitigate/block | This plan preserves target guard and enables later non-mutation proof; no command may target non-DGFY names. |
</threat_model>
