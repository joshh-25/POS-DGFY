<objective>
Create the additive per-business `dgfy_business_*` foundation and a safe runner target-selection mechanism for initial tenant coverage.

Purpose: DBF-03 requires a tenant/business database foundation for canonical locations, staff authorization profiles, account-to-staff assignment/link metadata, role/permission basics, terminal identity, and tenant-local ownership metadata. This plan implements locked decisions D-02, D-03, D-10, D-14, and D-15.

Output: target-scoped migration metadata, business schema contract, business foundation migration, runner target selection for one or more `dgfy_business_*` databases, tests, and documentation updates.
</objective>

<threat_model>
OWASP ASVS Level 1 framing: tenant database selection and authorization foundation are high-impact because future tenant sessions depend on them.

## Trust Boundaries
| Boundary | Description |
|---|---|
| Env/registry target list -> runner | Business DB names determine which tenant databases are mutated. |
| `dgfy_core.business_database_registry` -> `dgfy_business_*` | Registry integrity controls coverage and access routing later. |
| Tenant schema -> future backend tenant sessions | Role, staff, assignment, and terminal tables become authorization inputs. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-03-01 | Spoofing | business database target parser | high | mitigate/block | Reject all targets outside `dgfy_business_<stable_opaque_suffix>` before connection; never derive from display name. |
| T-02-03-02 | Repudiation | target-scoped migration metadata | high | mitigate/block | Record schema migrations by target database plus migration name so each business DB has independent evidence. |
| T-02-03-03 | Elevation of Privilege | `account_staff_assignments`, `roles`, `role_permissions` | high | mitigate/block | Add uniqueness/status constraints and assignment metadata required for later landlord+tenant authorization checks. |
| T-02-03-04 | Tampering | `terminal_identities` | medium | mitigate | Store terminal identity/status/policy metadata foundation without checkout/payment behavior. |
| T-02-03-05 | Information Disclosure | schema reports | medium | mitigate | Reports list database names and schema findings only; no DB credentials or secrets. |
| T-02-03-06 | Tampering | legacy `sku_*` schemas | high | mitigate/block | Target parser rejects legacy names; Plan 04 fingerprint proof validates non-mutation. |
</threat_model>
