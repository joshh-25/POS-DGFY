<objective>
Create the Phase 11 schema foundation: one additive `targetKind: 'business'` Sequelize migration that (a) adds three denormalized read-cache columns to the existing `availments` table, (b) creates the append-only `availment_stage_events` ledger, and (c) creates the `courier_assignments` table with a deliberately-mutable payout sub-lifecycle. Purpose: Every downstream plan (module usecases, finalize-seam auto-write, live apply) depends on these tables/columns/models existing and being reachable. This plan is the two-field event-sourced fulfillment-status shape (carried forward from the domain spec) made concrete.
Output: 1 new migration, 2 new models, `Availment.js` + `tenantConnector.js` + `dgfyBusinessContract.js` modified.

Locked decisions implemented here: D-01 (free-text courier columns, no reusable entity), D-02 (payout lifecycle columns), D-03 (courier payout table independent of shift pay-outs), D-04 (dedicated append-only courier-assignment table), D-10 (`is_forced` distinct override flag on stage events), D-15 (one shared `fulfillment_stage` string column, no per-mode DB constraint). Carrying-forward: two-field shape (coarse `fulfillment_status` + `fulfillment_stage`) + fixed enums.
Landmines honored: L1 (name the coarse column `fulfillment_status`, never reuse `availments.status`), L3/A5 (courier payout mutable — no append-only trigger on `courier_assignments`), L4 (register both models + associations), L5 (extend contract), A4 (new columns nullable, no backfill).

**Resolved research forks (dispositions locked in this plan, no cross-read of 11-RESEARCH.md needed):**
- **A4 (backfill pre-migration availments) → RESOLVED: no backfill** — the three new `availments` columns are nullable/additive; existing rows stay NULL.
- **A5 (courier payout mutability) → RESOLVED: mutable** — `courier_assignments` has `updated_at` and NO append-only trigger (append-only triggers scope to `availment_stage_events` only).
- **Open Q2 (record D-10 overrides distinctly) → RESOLVED: distinct queryable `is_forced` BOOLEAN column** on `availment_stage_events` (plus the free-text `reason`), not `reason` alone.
- **Open Q3 (single-table vs split payout) → RESOLVED: single table** — payout columns (`payout_amount`/`payout_status`/`paid_at`) live on `courier_assignments`; no separate payout table.
