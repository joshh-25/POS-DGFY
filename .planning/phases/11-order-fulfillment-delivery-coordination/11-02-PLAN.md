<objective>
Build the new `apps/dgfy-api/src/modules/fulfillment` Clean-Architecture module mirroring `modules/inventory`: two repositories (append-only stage events; courier assignments with mutable payout), the usecases layer carrying the `STAGE_SEQUENCES` frozen map + per-mode next-legal-stage validation (D-15 app-logic) + membership gating, a transport-only controller, the routes, and the DI wiring factory. Includes mock-Sequelize unit tests. The module's `buildFulfillmentModule()` also exposes a `recordStageEvents` port that the availments finalize seam consumes in Plan 03.

Purpose: This is the staff-facing surface for FUL-01 (view/process incoming orders), FUL-02 (progress the shared pipeline), and FUL-03 (assign courier + track payout). The linchpin is that per-mode valid-sequence enforcement lives in application logic, never the DB (D-15).
Output: 6 new module files + 2 unit test files.

Locked decisions implemented here: D-01 (free-text courier), D-02 (payout owed->paid lifecycle), D-04 (append-only courier identity, reassignment supersedes not overwrites), D-08 (queue scoped to online orders only), D-09/D-11 (staff marks completed; no customer-facing endpoint), D-10 (force-complete override), D-12/D-13/D-14 (exact per-mode stage names), D-15 (shared enum + app-logic sequence).
Discretionary resolutions surfaced: A3 (any-active-membership gate, not owner-only), Open Q4 (FUL-01 accepts optional `branch_id`/`fulfillment_mode` filters, default = all active online orders).
</objective>
