<objective>
Close FSC-02, the single remaining failed truth from 08-VERIFICATION.md (status: gaps_found, 6/7 verified). The 08-09 gap-closure correctly wired evaluateComplianceDecision()'s compliant_active POS branch to consult checklist.ready_for_compliant_activation, but the upstream function that produces that roll-up flag, evaluateComplianceChecklist() in policyEngine.js, computes its seven evidence-derived readiness signals with TWO inconsistent default policies: five signals use the `!== false` idiom (an omitted/undefined evidence field is silently treated as SATISFIED — fail-open), while only two use `=== true` (fail-closed on omission). A compliant_active business that supplies only the two fail-closed signals and omits the other five still reaches ALLOW for POS_CHECKOUT — a fail-open compliance/authorization bypass independently reproduced by the verifier via direct code execution.

This is a security defect (fail-open authorization bypass), not a design change. Option A (full-checklist enforcement) was already chosen and implemented for the wiring layer in 08-09; this plan only corrects the checklist's own per-signal default consistency so all seven signals fail closed uniformly, and adds the partial-evidence regression test that the existing suite is missing.

Purpose: Make the shared compliance gate port actually enforce every readiness signal it documents, so Phase 9 inherits a gate that cannot be silently bypassed by a caller that omits an evidence field.
Output: Uniform fail-closed defaults in evaluateComplianceChecklist() + one new regression test proving the partial-evidence bundle yields REQUIRES_SETUP.
</objective>
