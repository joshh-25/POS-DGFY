<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reference seam ↔ SOURCE_DB (legacy backup) | The seam connects to the live legacy backup database; it must be read-only so it cannot corrupt legacy domains. |
| manifest/config strings ↔ SQL | Table/domain identifiers used by the probe must never be interpolated unsafely into SQL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Tampering / DoS | destructive write to SOURCE_DB corrupts the legacy backup | medium | mitigate | Seam is read-only by construction (SHOW TABLES / COUNT / integrity probes only); no write/DDL statements; any future write must pass the runner's assertDestructiveAllowed() gate — never bypass (Task 1). Impact would be high but likelihood is low given the read-only construction and the existing destructive-op gate. |
| T-05-06 | Tampering | SQL injection via domain/table identifiers in the probe | medium | mitigate | Validate all identifiers against the explicit expected-table allowlist before use; parameterize queries; never interpolate manifest/config strings into SQL (Task 1, follows createLegacyTenantSourceConnection defensive validation). |
| T-05-07 | Information Disclosure | raw legacy rows leaked into the JSON report or inventory doc | low | mitigate | Report payload carries only table names, counts, and booleans — no raw rows (Task 1, mirrors Phase 3 report-field allowlisting). |
| T-05-SC | Tampering | npm dependency surface | low | accept | No new package installed (reuses the runner's existing sequelize/mysql2/commander stack); no supply-chain checkpoint required. |
</threat_model>
