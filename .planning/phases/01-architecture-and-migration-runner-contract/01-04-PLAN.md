  <action>
    Create `infrastructure/docker/dgfy-migration-runner/Dockerfile` following `infrastructure/docker/dgfy-api/Dockerfile`'s exact two-stage shape. Header: `# syntax=docker/dockerfile:1` plus a build-context comment (`# Build context: repo root (contains apps/dgfy-migration-runner/)`). Stage `deps`: `FROM node:22-alpine AS deps`, `WORKDIR /app`, `COPY apps/dgfy-migration-runner/package*.json ./`, `RUN npm ci --omit=dev`. Stage `runtime`: `FROM node:22-alpine AS runtime`, `ENV NODE_ENV=production`, `WORKDIR /app`, `RUN apk add --no-cache tini su-exec && addgroup -S app && adduser -S app -G app` (no `curl` — unlike `dgfy-api` there is no `HEALTHCHECK` to curl against, since this is a one-shot CLI, not a long-running HTTP service, per RUN-01's "separate from long-running backend/API containers"), `COPY --from=deps /app/node_modules ./node_modules`, `COPY apps/dgfy-migration-runner/package*.json ./`, `COPY apps/dgfy-migration-runner/src ./src`, `RUN mkdir -p /reports && chown -R app:app /app /reports` (the writable bind mount is `/reports`, mapped to `REPORT_DIR` per D-13 — NOT `/app/logs` like `dgfy-api`), `COPY infrastructure/docker/dgfy-migration-runner/entrypoint.sh /usr/local/bin/entrypoint.sh`, `RUN chmod +x /usr/local/bin/entrypoint.sh`. Deliberately OMIT `EXPOSE` and `HEALTHCHECK` (both present in `dgfy-api`'s Dockerfile) — this container never listens on a port. `ENTRYPOINT ["/sbin/tini", "--", "/usr/local/bin/entrypoint.sh"]`, `CMD ["node", "src/cli.js", "--help"]` (running the bare image with no args prints help instead of silently doing nothing or erroring — matches D-04's "explicit, discoverable via --help" spirit).
