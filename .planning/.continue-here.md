## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| MySQL named-lock + Sequelize connection pool mismatch | GET_LOCK/RELEASE_LOCK are session-scoped; a naive `coreSequelize.query('SELECT GET_LOCK(...)')` followed later by a separate `.query('SELECT RELEASE_LOCK(...)')` can silently execute on two *different* pooled connections, making the lock a no-op with no error. | advisory | Any future concurrency-guard fix using MySQL named locks with Sequelize must pin both calls to one physical connection (Sequelize's unmanaged-transaction-as-connection-affinity-handle technique), and must be honestly labeled as unverified-against-real-concurrency if no live MySQL is available to test against. |
| macOS `/tmp` → `/private/tmp` symlink breaks path-relative architecture guardrails | When running an isolated git worktree under `/tmp/...`, `apps/dgfy-api`'s `check-architecture-guardrails.js` mixes `$PWD`-derived paths (symlinked) with `__dirname`-derived paths (resolved), producing false-positive `controllerNaming` violations that block commits. | advisory | Always `cd` into the `realpath`-resolved form of any worktree created under `/tmp` (i.e. `/private/tmp/...` on macOS) before running guardrail scripts or committing. |

_No blocking constraints — both rows above are advisory only._
