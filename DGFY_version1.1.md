# Discover Goods For You (DGFY)

## Document Purpose

This document defines the official brand, interface, and frontend implementation standards for the DGFY ecosystem.

It applies to:

- DGFY Marketplace
- DGFY POS
- DGFY mobile applications
- DGFY web dashboards
- DGFY business tools
- DGFY marketing websites
- Future DGFY platform extensions

All designers, frontend developers, backend developers, QA testers, content creators, and product managers should follow this standard to keep DGFY consistent, accessible, scalable, and production-ready.

---

# 1. Brand Overview

## Brand Name

DGFY

## Full Meaning

Discover Goods For You

## Brand Mission

To help people discover products, services, stores, and opportunities around them through a location-based digital marketplace platform.

## Brand Vision

To become a leading local discovery platform that connects consumers with businesses through intelligent search, mapping, and digital commerce.

## Brand Personality

DGFY should always feel:

- Modern
- Reliable
- Helpful
- Fast
- Discoverable
- Innovative
- Accessible
- Professional

DGFY should avoid:

- Overly playful visuals
- Excessive animations
- Cluttered interfaces
- Outdated UI patterns
- Difficult navigation
- Decorative elements that reduce usability
- Inconsistent branding across products

# 4. Logo Standards

## Primary Logo

The primary DGFY logo is the wordmark with the integrated location/search symbol.

### Usage

Use the primary logo for:

- Website headers
- Mobile applications
- Marketing materials
- Presentations
- Official documents
- Customer-facing brand placements

### Minimum Size

Desktop:

- 120px width

Mobile:

- 90px width

## Horizontal Logo

The horizontal logo is preferred for interface headers, POS sidebars, navigation areas, and compact brand placements.

### Usage

Use the horizontal logo for:

- POS sidebar logo area
- Website navigation bars
- Footer branding
- Partner branding
- Co-branding placements

## Logo Mark

The logo mark is the location pin/search icon without the wordmark.

### Usage

Use the logo mark for:

- App icon
- Favicon
- Social media profile image
- Loading screen
- Compact mobile UI
- Small icon-only placements

## Clear Space

Maintain clear space around the logo equal to at least one logo-mark width where possible.

No text, graphics, buttons, or UI elements should crowd the logo.

## Background Usage

Preferred backgrounds:

- White
- Transparent
- Ocean Blue when using a white logo
- High-contrast neutral backgrounds

Avoid placing the logo on:

- Low-contrast images
- Busy backgrounds
- Heavy gradients
- Patterned surfaces that reduce legibility

## Incorrect Usage

Do not:

- Stretch the logo
- Compress the logo
- Rotate the logo
- Change logo colors
- Apply gradients
- Add shadows
- Distort proportions
- Crop the logo
- Place on low-contrast backgrounds

# 11. Button Standards

## Primary Button

Background:

- `#1A4E8D`

Text:

- `#FFFFFF`

Height:

- 44px-48px

Radius:

- 8px-12px

Usage:

- Checkout
- Save
- Continue
- Confirm
- Submit
- Primary workflow actions

## Secondary Button

Background:

- Transparent or white

Border:

- `1px solid #1A4E8D`

Text:

- `#1A4E8D`

Usage:

- Secondary actions
- Optional actions
- View details
- Filters

## Danger Button

Background:

- `#DC2626`

Text:

- `#FFFFFF`

Usage:

- Delete
- Reject
- Void
- Cancel critical action

## Disabled Button

Background:

- Gray 100 or muted surface

Text:

- Gray 500

Rules:

- Disabled buttons must clearly appear unavailable.
- Disabled states should not rely on opacity alone when clarity is needed.

## Button Rules

- Primary action must be visually obvious.
- Avoid multiple primary buttons in one section.
- Touch targets must be at least 44px high.
- Button labels must be clear and action-based.
- Icon-only buttons require accessible labels or tooltips.

# 12. Card Standards

All cards should use:

- White background
- 8px-12px radius for POS/admin
- 12px-16px radius for marketplace/web
- Consistent elevation
- 16px-24px padding
- Clear visual hierarchy

## Supported Card Types

- Product Card
- Service Card
- Store Card
- Booking Card
- Order Card
- Notification Card
- POS Status Card
- Cart Item Card
- Setup Card
- Compliance Card
- Dashboard Metric Card

## Card Rules

Avoid:

- Cards inside cards unless required
- Oversized cards in dense operational screens
- Decorative cards that do not support a user task
- Too many cards competing for attention

For POS:

- Cards must support fast decision-making.
- Cards should not block the checkout workflow.
- Status cards should be useful but not dominant.

# 14. Forms & Inputs

## Input Standards

Inputs should use:

- White background
- Clear border
- 8px-12px radius
- Visible focus state
- Label or accessible name
- Helpful placeholder only when useful

## Validation

Validation messages should:

- Explain the problem clearly
- Tell the user how to fix it
- Appear near the affected field
- Use semantic error color

## Required Fields

Required fields should be clearly indicated when necessary.

Avoid relying only on placeholder text for critical instructions.

---

# 15. Notifications & Alerts

## Success Notifications

Use for completed actions.

Examples:

- Shift opened.
- Checkout completed.
- Settings saved.

## Warning Notifications

Use for conditions that need attention but do not block the user.

Examples:

- Terminal policy warning.
- Sync queue has pending items.

## Error Notifications

Use when an action fails or is blocked.

Examples:

- Checkout failed.
- Compliance requirement incomplete.
- Unable to connect.

## Notification Rules

- Keep messages short.
- Avoid technical stack traces.
- Give next steps when possible.
- Do not show duplicate messages for the same event.

# 16. Mobile Design Standards

## Target Mobile Width

390px

## Mobile Requirements

- Safe area support required
- Minimum touch target: 44px by 44px
- Avoid horizontal scrolling
- Keep primary actions reachable
- Use readable text sizes
- Avoid dense desktop-only layouts on mobile

## Bottom Navigation

Maximum:

- 5 items

Recommended marketplace navigation:

- Home
- Explore
- Orders
- Messages
- Profile

## Mobile Product Priority

Marketplace and consumer discovery experiences should be mobile-first.

POS and admin tools should be workflow-first and responsive across tablet, desktop, and mobile where practical.

# 17. Accessibility Standards

## Minimum Contrast Ratio

4.5:1 for normal text.

## Minimum Touch Target

44px by 44px.

## Requirements

- Keyboard navigation support
- Proper ARIA labels
- Screen reader compatibility
- Accessible color combinations
- Visible focus states
- Form labels must be clear
- Error messages must explain the problem and next action
- Interactive elements must be reachable without a mouse

## Accessibility Rules

Do not:

- Use color alone to communicate status
- Remove visible focus styles
- Use tiny touch targets
- Hide important content from assistive technology

---

# 18. UI Design Principles

## Discoverability

Users must immediately understand available actions.

## Simplicity

Reduce unnecessary clicks and complexity.

## Consistency

Maintain predictable behavior across the platform.

## Speed

Interfaces should feel fast and responsive.

## Mobile First Where Appropriate

Marketplace and consumer experiences should prioritize mobile.

Operational tools such as POS should prioritize fast workflows first.

## Location First

For marketplace and discovery products, maps and nearby search are central.

For POS, location means:

- Operating location
- Store scope
- Fulfillment location
- Terminal identity

# 20. DGFY POS Interface Standards

DGFY POS should feel:

- Fast
- Clear
- Operational
- Low-clutter
- Touch-friendly
- Cashier-focused
- Professional

## POS Priorities

POS screens should prioritize:

- Sell / checkout action
- Cart visibility
- Product search
- Barcode scanning
- Shift status
- Order queue
- Sync queue
- Terminal identity
- Location scope
- Compliance status

## POS Layout Rules

- Keep the Sell workflow easy to access.
- Keep cart and checkout actions visible.
- Avoid marketing-style hero sections.
- Avoid oversized decorative UI.
- Avoid unnecessary cards that reduce workspace.
- Sidebar navigation should be clear and compact.
- Status cards should support operational awareness without blocking the main workflow.
- Internal Sell tabs such as Checkout, History, and Receipt Preview should keep Sell highlighted in navigation.

## POS Logo Rule

Use the DGFY horizontal logo in the POS sidebar/header.

Desktop POS logo width:

- 120px

Mobile POS logo width:

- 90px

Logo background should remain transparent unless contrast requires a brand-colored container.

## POS Button Rules

Primary POS actions:

- Checkout
- Open Shift
- Close Shift
- Replay Sync Queue
- Update Order Status

These actions must be easy to find and large enough for touch use.

## POS Density Rules

POS must preserve workspace.

Avoid:

- Oversized headers
- Large empty logo areas
- Repeated navigation for the same action
- Sticky cards that block scrolling
- Decorative content that slows cashier work

# 24. Content Rules

## UI Text

UI text should be:

- Short
- Actionable
- Specific
- Easy to translate later

## Empty States

Empty states should explain:

- What is missing
- Why it matters
- What the user can do next

## Error States

Error states should explain:

- What failed
- Whether the user can retry
- What action is needed

Avoid exposing raw technical errors to end users.

# 25. Governance

This document is the official source of truth for DGFY branding and frontend implementation.

All new products, features, interfaces, and marketing materials should comply with these standards before release.

Any updates to this design system must be documented, reviewed, and approved before implementation.

Product-specific exceptions are allowed only when they improve usability, accessibility, or operational performance.

Exceptions should be documented with:

- Reason
- Product area affected
- Approved alternative
- Review date
